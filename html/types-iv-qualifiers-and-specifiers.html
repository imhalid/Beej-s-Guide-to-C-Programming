16 Türler IV: Niteleyiciler ve Belirteçler

Artık elimizin altında birkaç tür daha olduğuna göre, bu türlere davranışlarını kontrol eden bazı ek nitelikler kazandırabileceğimiz ortaya çıkıyor. Bunlar tür niteleyicileri (type qualifiers) ve depolama sınıfı belirteçleridir (storage-class specifiers).

16.1 Tür Niteleyicileri

Bunlar sabit değerler bildirmenize ve ayrıca derleyiciye kullanabileceği optimizasyon ipuçları vermenize olanak tanır.

16.1.1 const

Bu, göreceğiniz en yaygın tür niteleyicisidir. Değişkenin sabit olduğu anlamına gelir ve onu değiştirme yönündeki her türlü girişim, derleyicinin fazlasıyla öfkelenmesiyle sonuçlanır.

const int x = 2;

x = 4;  // DERLEYİCİ KUSMA SESLERİ, bir sabite atama yapılamaz

Bir const değerini değiştiremezsiniz.

Genellikle const ifadesini fonksiyonların parametre listelerinde görürsünüz:

void foo(const int x)
{
    printf("%d\n", x + 30);  // OK, "x"i değiştirmez
}

16.1.1.1 const ve Pointer'lar

Bu konu biraz kafa karıştırıcı olabilir, çünkü pointer'lar söz konusu olduğunda iki farklı kullanım ve iki farklı anlam vardır.

Birincisi, pointer'ın işaret ettiği şeyi değiştirilemez hale getirebiliriz. Bunu, tür bildiriminde const ifadesini tür adının önüne (yıldız işaretinden önce) koyarak yaparsınız.

int x[] = {10, 20};
const int *p = x; 

p++;  // p'yi değiştirebiliriz, sorun yok

*p = 30; // Derleyici hatası! İşaret ettiği şeyi değiştiremezsiniz

Biraz kafa karıştırıcı olsa da, şu iki ifade birbirine eşdeğerdir:

const int *p;  // p'nin işaret ettiği şey değiştirilemez
int const *p;  // Önceki satırla aynı şekilde p'nin işaret ettiği şey değiştirilemez

Harika, yani pointer'ın gösterdiği şeyi değiştiremiyoruz, ama pointer'ın kendisini değiştirebiliyoruz. Peki tam tersini istersek? Pointer'ın gösterdiği şeyi değiştirebilmek, ama pointer'ın kendisini değiştirememek istersek?

Bildirimde const anahtar kelimesini yıldız işaretinden sonraya taşımanız yeterlidir:

int *const p;   // "p" değerini pointer aritmetiği ile değiştiremeyiz

p++;  // Derleyici hatası!

Fakat işaret ettikleri değeri değiştirebiliriz:

int x = 10;
int *const p = &x;

*p = 20;   // "x" değerini 20 yap, sorun yok

Ayrıca her iki şeyi de const yapabilirsiniz:

const int *const p;  // Ne p'yi ne de *p'yi değiştirebilirsiniz!

Son olarak, birden fazla dolaylı yönlendirme (indirection) seviyeniz varsa, uygun seviyeleri const yapmalısınız. Bir pointer'ın const olması, işaret ettiği pointer'ın da const olması gerektiği anlamına gelmez. Aşağıdaki örneklerde olduğu gibi bunları açıkça belirtebilirsiniz:

char **p;
p++;     // OK!
(*p)++;  // OK!

char **const p;
p++;     // Hata!
(*p)++;  // OK!

char *const *p;
p++;     // OK!
(*p)++;  // Hata!

char *const *const p;
p++;     // Hata!
(*p)++;  // Hata!

16.1.1.2 const Doğruluğu (Const Correctness)

Bahsetmem gereken bir şey daha var: Derleyici şuna benzer bir durumda uyarı verecektir:

const int x = 20;
int *p = &x;

şuna benzer bir şey söyleyerek:

initialization discards 'const' qualifier from pointer type target

Orada ne oluyor?

Atamanın her iki tarafındaki türlere bakmamız gerekiyor:

    const int x = 20;
    int *p = &x;
//    ^       ^
//    |       |
//  int*    const int*

Derleyici, atamanın sağ tarafındaki değerin const olduğu, ancak sol tarafındakinin olmadığı konusunda bizi uyarıyor. Ve derleyici, sağdaki ifadenin "const-luk" özelliğini göz ardı ettiğini bize bildiriyor.

Yani, yine de aşağıdakini yapmayı deneyebiliriz, ancak bu sadece yanlıştır. Derleyici uyarı verecektir ve bu tanımsız davranıştır (undefined behavior):

const int x = 20;
int *p = &x;

*p = 40;  // Tanımsız davranış--belki "x"i değiştirir, belki değiştirmez!

printf("%d\n", x);  // Şanslıysanız 40

16.1.2 restrict

Özetle (TLDR): Bunu asla kullanmak zorunda değilsiniz ve ne zaman görseniz göz ardı edebilirsiniz. Doğru kullanırsanız, muhtemelen bir performans artışı sağlarsınız. Yanlış kullanırsanız, tanımsız davranış (undefined behavior) ile karşılaşırsınız.

restrict, derleyiciye belirli bir bellek bölgesine yalnızca tek bir pointer tarafından erişileceği ve başka hiçbir pointer tarafından erişilmeyeceği yönünde verilen bir ipucudur. (Yani, restrict pointer'ının işaret ettiği nesnenin başka bir takma adı [aliasing] olmayacaktır.) Bir geliştirici bir pointer'ı restrict olarak bildirir ve ardından işaret ettiği nesneye başka bir yolla (örneğin başka bir pointer üzerinden) erişirse, davranış tanımsızdır.

Temel olarak C'ye şöyle diyorsunuz: "Hey—bu bellek alanına eriştiğim tek yolun bu tek pointer olduğuna garanti veriyorum ve yalan söylüyorsam üzerime tanımsız davranış salabilirsin."

Ve C bu bilgiyi belirli optimizasyonları gerçekleştirmek için kullanır. Örneğin, bir döngü içinde restrict pointer'ının değerini tekrar tekrar dolaylı olarak okuyorsanız (dereference), C sonucu bir yazmaçta (register) önbelleğe almaya ve son sonucu yalnızca döngü tamamlandığında saklamaya karar verebilir. Başka bir pointer aynı belleğe başvurup döngü içinde ona erişseydi, sonuçlar doğru olmazdı.

(Not: İşaret edilen nesneye hiçbir zaman yazılmıyorsa restrict niteleyicisinin hiçbir etkisi yoktur. Her şey belleğe yapılan yazmalarla ilgili optimizasyonlarla ilgilidir.)

İki değişkenin değerini takas eden (swap) bir fonksiyon yazalım ve C'ye aynı nesneye işaret eden pointer'ları asla geçirmeyeceğimizin güvencesini vermek için restrict anahtar kelimesini kullanalım. Ve ardından işi batırıp aynı nesneye işaret eden pointer'lar geçirmeyi deneyelim.

void swap(int *restrict a, int *restrict b)
{
    int t;

    t = *a;
    *a = *b;
    *b = t;
}

int main(void)
{
    int x = 10, y = 20;

    swap(&x, &y);  // OK! Yukarıdaki "a" ve "b" farklı şeyleri işaret ediyor

    swap(&x, &x);  // Tanımsız davranış! "a" ve "b" aynı şeyi işaret ediyor
}

Yukarıdaki restrict anahtar kelimelerini çıkarsaydık, bu her iki çağrının da güvenli bir şekilde çalışmasını sağlardı. Ancak o zaman derleyici optimizasyon yapamayabilirdi.

restrict blok kapsamına (block scope) sahiptir, yani kısıtlama yalnızca kullanıldığı kapsam süresince geçerlidir. Bir fonksiyonun parametre listesindeyse, o fonksiyonun blok kapsamındadır.

Kısıtlanmış pointer bir diziye işaret ediyorsa, kısıtlama yalnızca dizideki bireysel nesnelere uygulanır. Başka pointer'lar, kısıtlanmış pointer ile aynı elemanlardan herhangi birini okumadıkları veya yazmadıkları sürece diziden okuma ve yazma yapabilirler.

Herhangi bir fonksiyonun dışında dosya kapsamında (file scope) ise, kısıtlama tüm programı kapsar.

Bunu printf() gibi kütüphane fonksiyonlarında görmeniz muhtemeldir:

int printf(const char * restrict format, ...);

Yine bu, derleyiciye printf() fonksiyonu içinde bu format string'inin herhangi bir parçasına başvuran yalnızca tek bir pointer olacağını söyler.

Son bir not: Bir sebepten dolayı fonksiyon parametrenizde pointer gösterimi yerine dizi gösterimi kullanıyorsanız, restrict ifadesini şu şekilde kullanabilirsiniz:

void foo(int p[restrict])     // Boyut olmadan

void foo(int p[restrict 10])  // Veya bir boyut ile

Ancak pointer gösterimi daha yaygındır.

16.1.3 volatile

Doğrudan donanımla ilgilenmediğiniz sürece bunu görmeniz veya buna ihtiyaç duymanız pek olası değildir.

volatile, derleyiciye bir değerin arkasından gizlice değişebileceğini ve her defasında yeniden bakılması gerektiğini söyler.

Bir örnek: Derleyicinin bellekte arka planda sürekli güncellenen bir adrese bakması olabilir, örneğin bir tür donanım zamanlayıcısı (timer).

Derleyici bunu optimize etmeye ve değeri uzun süre bir yazmaçta (register) tutmaya karar verirse, bellekteki değer güncellenecek ve yazmaca yansımayacaktır.

Bir şeyi volatile olarak bildirerek derleyiciye şöyle demiş olursunuz: "Hey, bu şeyin işaret ettiği değer bu program kodunun dışındaki nedenlerden dolayı her an değişebilir."

volatile int *p;

16.2 Depolama Sınıfı Belirteçleri

Depolama sınıfı belirteçleri tür niteleyicilerine benzer. Derleyiciye bir değişkenin türü hakkında daha fazla bilgi verirler.

16.2.1 auto

Bu anahtar kelimeyi neredeyse hiç görmezsiniz, çünkü auto blok kapsamındaki (block scope) değişkenler için varsayılandır. Örtük olarak mevcuttur.

Şunlar aynıdır:

{
    int a;         // auto varsayılandır...
    auto int a;    // Dolayısıyla bu gereksizdir
}

auto anahtar kelimesi, bu nesnenin otomatik depolama süresine (automatic storage duration) sahip olduğunu gösterir. Yani tanımlandığı kapsam içinde var olur ve kapsamdan çıkıldığında otomatik olarak bellekten kaldırılır.

Otomatik değişkenlerle ilgili bir püf nokta, açıkça ilk değer ataması (initialize) yapana kadar değerlerinin belirsiz olmasıdır. İçlerinin "rastgele" veya "çöp" veriyle dolu olduğunu söyleriz, her ne kadar bu ifadelerin ikisi de beni pek mutlu etmese de. Her halükarda, ilk değer atamadığınız sürece içinde ne olduğunu bilemezsiniz.

Tüm otomatik değişkenleri kullanmadan önce her zaman ilk değerle başlatın!

16.2.2 static

Bu anahtar kelime, değişkenin dosya kapsamında mı yoksa blok kapsamında mı olduğuna bağlı olarak iki farklı anlama gelir.

Blok kapsamı (block scope) ile başlayalım.

16.2.2.1 Blok Kapsamında static

Bu durumda temel olarak şöyle demiş oluyoruz: "Bu değişkenin çağrılar arasında paylaşılan tek bir örneğinin var olmasını istiyorum."

Yani değeri fonksiyon çağrıları arasında korunacaktır.

Bir ilk değer ataması içeren blok kapsamındaki static, fonksiyon her çağrıldığında değil, yalnızca program başlatıldığında bir kez ilk değerini alır.

Bir örnek yapalım:

#include <stdio.h>

void counter(void)
{
    static int count = 1;  // Bu bir kez başlatılır

    printf("This has been called %d time(s)\n", count);

    count++;
}

int main(void)
{
    counter();  // "This has been called 1 time(s)"
    counter();  // "This has been called 2 time(s)"
    counter();  // "This has been called 3 time(s)"
    counter();  // "This has been called 4 time(s)"
}

count değişkeninin değerinin çağrılar arasında nasıl korunduğunu gördünüz mü?

Dikkat edilmesi gereken bir husus, blok kapsamındaki static değişkenlerin varsayılan olarak 0 değeriyle başlatılmasıdır.

static int foo;      // Varsayılan başlangıç değeri `0` dır...
static int foo = 0;  // Dolayısıyla `0` ataması gereksizdir

Son olarak, çoklu izlekli (multithreaded) programlar yazıyorsanız, birden fazla izleğin (thread) aynı değişkeni çiğnemesine izin vermediğinizden emin olmanız gerektiği konusunda uyarılalım.

16.2.2.2 Dosya Kapsamında static

Herhangi bir bloğun dışında, dosya kapsamına çıktığınızda anlam oldukça değişir.

Dosya kapsamındaki değişkenler zaten fonksiyon çağrıları arasında varlığını sürdürür, dolayısıyla bu davranış zaten mevcuttur.

Bunun yerine static anahtar kelimesinin bu bağlamdaki anlamı, bu değişkenin söz konusu kaynak dosya dışında görünür olmamasıdır. Bir nevi "küresel" (global) gibidir, ancak yalnızca bu dosya içindedir.

Birden fazla kaynak dosyasıyla derleme yapma hakkındaki bölümde bununla ilgili daha fazla bilgi bulabilirsiniz.

16.2.3 extern

extern depolama sınıfı belirteci, diğer kaynak dosyalardaki nesnelere başvurmamızı sağlar.

Örneğin, bar.c dosyasının içeriğinin tamamen şundan ibaret olduğunu varsayalım:

// bar.c

int a = 37;

Sadece bu kadar. Dosya kapsamında yeni bir int a bildirimi.

Peki ya foo.c adında başka bir kaynak dosyamız olsaydı ve bar.c içindeki a değişkenine başvurmak isteseydik?

extern anahtar kelimesi ile bu çok kolaydır:

// foo.c

extern int a;

int main(void)
{
    printf("%d\n", a);  // bar.c'den gelen 37!

    a = 99;

    printf("%d\n", a);  // bar.c'deki aynı "a", ama artık 99
}

Ayrıca extern int a bildirimini blok kapsamında da yapabilirdik ve yine de bar.c içindeki a değişkenine başvuruyor olurdu:

// foo.c

int main(void)
{
    extern int a;

    printf("%d\n", a);  // bar.c'den gelen 37!

    a = 99;

    printf("%d\n", a);  // bar.c'deki aynı "a", ama artık 99
}

Şimdi, eğer bar.c içindeki a değişkeni static olarak işaretlenmiş olsaydı bu çalışmazdı. Dosya kapsamındaki static değişkenler o dosyanın dışında görünür değildir.

Fonksiyonlarda extern kullanımı hakkında son bir not. Fonksiyonlar için extern varsayılardır, bu yüzden kullanımı gereksizdir. Bir fonksiyonun yalnızca tek bir kaynak dosyada görünür olmasını istiyorsanız onu static olarak bildirebilirsiniz.

16.2.4 register

Bu, derleyiciye bu değişkenin sık kullanıldığı ve erişiminin mümkün olduğunca hızlı yapılması gerektiği yönünde ipucu veren bir anahtar kelimedir. Derleyicinin buna uyma zorunluluğu yoktur.

Günümüzde modern C derleyici optimizasyon araçları bunu kendileri belirlemede oldukça başarılıdır, bu yüzden bugünlerde bunu görmek nadirdir.

Ama yine de kullanmak isterseniz:

#include <stdio.h>

int main(void)
{
    register int a;   // "a" değişkeninin kullanımını olabildiğince hızlı yap.

    for (a = 0; a < 10; a++)
        printf("%d\n", a);
}

Ancak bunun bir bedeli vardır. Bir register değişkeninin adresini alamazsınız:

register int a;
int *p = &a;    // DERLEYİCİ HATASI! Bir register'ın adresi alınamaz

Aynı durum bir dizinin herhangi bir parçası için de geçerlidir:

register int a[] = {11, 22, 33, 44, 55};
int *p = a;  // DERLEYİCİ HATASI! a[0]'ın adresi alınamaz

Veya dizinin bir elemanının değerini dolaylı yoldan almak için de:

register int a[] = {11, 22, 33, 44, 55};

int a = *(a + 2);  // DERLEYİCİ HATASI! a[0]'ın adresi alındı

İlginç bir şekilde, dizi gösterimiyle eşdeğer olan kullanım için gcc yalnızca uyarı verir:

register int a[] = {11, 22, 33, 44, 55};

int a = a[2];  // DERLEYİCİ UYARISI!

şununla:

warning: ISO C forbids subscripting ‘register’ array

Bir register değişkeninin adresini alamıyor oluşunuz, derleyici henüz bu optimizasyonu yapmadıysa bile bu varsayım etrafında optimizasyon yapabilmesini sağlar. Ayrıca const bir değişkene register eklemek, onun pointer'ının constness özelliğini kasten göz ardı eden başka bir fonksiyona kazara geçirilmesini önler117.

Burada biraz tarihsel arka plan bilgisi verelim: İşlemcinin (CPU) derinliklerinde yazmaçlar (registers)118 adı verilen küçük özel "değişkenler" bulunur. Bunlara erişim RAM'e kıyasla süper hızlıdır, dolayısıyla bunları kullanmak size hız artışı sağlar. Ancak RAM'de olmadıkları için ilişkili bir bellek adresleri yoktur (bu yüzden adreslerini alamaz veya onlara işaret eden bir pointer elde edemezsiniz).

Fakat söylediğim gibi, modern derleyiciler register anahtar kelimesini belirtip belirtmediğinize bakmaksızın mümkün olan her durumda yazmaçları kullanarak optimum kod üretme konusunda gerçekten çok iyidir. Sadece bu da değil, standart derleyicilerin isterlerse buna sanki auto yazmışsınız gibi davranmalarına da izin verir. Dolayısıyla bir garanti yoktur.

16.2.5 _Thread_local

Birden fazla izlek (thread) kullandığınızda ve küresel ya da static blok kapsamında bazı değişkenleriniz olduğunda, her izleğin değişkenin kendi kopyasını almasını sağlamanın yolu budur. Bu, yarış koşullarından (race conditions) ve izleklerin birbirinin ayağına basmasından kaçınmanıza yardımcı olur.

Blok kapsamındaysanız, bunu extern veya static ile birlikte kullanmanız gerekir.

Ayrıca <threads.h> başlık dosyasını dahil ederseniz, daha çirkin olan _Thread_local yerine daha göze hoş gelen thread_local takma adını kullanabilirsiniz.

Daha fazla bilgi İzlekler (Threads) bölümünde bulunabilir.
