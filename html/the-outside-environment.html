18 Dış Çevre

Bir programı çalıştırdığınızda, aslında siz kabuğa (shell) "Hey, lütfen bunu çalıştır" dersiniz. Kabuk da "Tabii ki" der ve ardından işletim sistemine "Hey, lütfen yeni bir süreç (process) oluşturup bunu çalıştırır mısın?" der. Eğer her şey yolunda giderse, işletim sistemi bunu kabul eder ve programınız çalışır.

Ancak programınızın dışında, kabuk içinde C kodunun içinden etkileşime girilebilecek koca bir dünya vardır. Bu bölümde bunlardan birkaçına göz atacağız.

18.1 Komut Satırı Argümanları

Birçok komut satırı aracı komut satırı argümanları kabul eder. Örneğin, Unix benzeri bir sistemde .txt ile biten tüm dosyaları görmek istersek şöyle bir şey yazabiliriz:

ls *.txt

(veya Windows sisteminde ls yerine dir).

Bu durumda komut lstir, ancak argümanları .txt ile biten tüm dosyalardır120.

Peki komut satırından programa ne aktarıldığını nasıl görebiliriz?

Diyelim ki komut satırında iletilen tüm sayıları toplayan ve sonucu yazdıran add adında bir programımız var:

./add 10 30 5
45

Faturaları ödeyeceği kesin!

Ama ciddileşmek gerekirse, bu komut satırından o argümanları nasıl alacağımızı ve onları nasıl ayrıştıracağımızı görmek için harika bir araçtır.

Öncelikle, onları nasıl elde edeceğimize bakalım. Bunun için yeni bir main() fonksiyonuna ihtiyacımız olacak!

İşte tüm komut satırı argümanlarını yazdıran bir program. Örneğin, yürütülebilir dosyayı foo olarak adlandırırsak, onu şöyle çalıştırabiliriz:

./foo i like turtles

ve şu çıktıyı görürüz:

arg 0: ./foo
arg 1: i
arg 2: like
arg 3: turtles

Biraz garip görünebilir, çünkü sıfırıncı argüman yürütülebilir dosyanın kendisinin adıdır. Ama bu sadece alışılması gereken bir durumdur. Argümanların kendileri hemen ardından gelir.

Kaynak kod:

#include <stdio.h>

int main(int argc, char *argv[])
{
    for (int i = 0; i < argc; i++) {
        printf("arg %d: %s\n", i, argv[i]);
    }
}

Vay canına! main() fonksiyon imzasında neler oluyor? argc ve argv121 (arg-si ve arg-vi olarak okunur) nedir?

Kolay olanla başlayalım: argc. Bu, program adının kendisi de dahil olmak üzere argüman sayısıdır (argument count). Tüm argümanları bir metin dizisi (string) dizisi olarak düşünürseniz — ki tam olarak öyledirler —, argc değerini o dizinin uzunluğu olarak düşünebilirsiniz — ki tam olarak öyledir.

Dolayısıyla bu döngüde yaptığımız şey, tüm argv ögelerini dolaşmak ve onları teker teker yazdırmaktır, böylece verilen bir girdi için:

./foo i like turtles

karşılık gelen çıktıyı elde ederiz:

arg 0: ./foo
arg 1: i
arg 2: like
arg 3: turtles

Bunu aklımızda tutarak, toplama programımızla devam etmeye hazırız.

Planımız:

  • Tüm komut satırı argümanlarına bakın (argv[0] yani program adından sonrakilere)
  • Onları tamsayılara dönüştürün
  • Onları yürütülen bir toplama ekleyin
  • Sonucu yazdırın

Hadi yapalım!

#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv)
{
    int total = 0;

    for (int i = 1; i < argc; i++) {  // 1'den başla, ilk argüman
        int value = atoi(argv[i]);    // Daha iyi hata yönetimi için strtol() kullanın

        total += value;
    }

    printf("%d\n", total);
}

Örnek çalıştırmalar:

$ ./add
0
$ ./add 1
1
$ ./add 1 2
3
$ ./add 1 2 3
6
$ ./add 1 2 3 4
10

Tabii ki, tamsayı olmayan bir değer girerseniz kusabilir, ancak buna karşı önlem almak okuyucuya bir alıştırma olarak bırakılmıştır.

18.1.1 Son argv Değeri NULL'dır

argv hakkında eğlenceli bir önbilgi, son metin dizisinden (string) sonra gelen elemanın NULL işaretçisi (pointer) olmasıdır.

Yani:

argv[argc] == NULL

her zaman doğrudur!

Bu anlamsız görünebilir, ancak birkaç yerde faydalı olduğu ortaya çıkar; şimdi bunlardan birine göz atacağız.

18.1.2 Alternatif: char **argv

Bir fonksiyon çağırdığınızda, C dilinin fonksiyon imzasında dizi notasyonu ile pointer notasyonu arasında bir fark gözetmediğini hatırlayın.

Yani şunlar aynıdır:

void foo(char a[])
void foo(char *a)

Şimdi, argv ifadesini bir string dizisi, yani bir char* dizisi olarak düşünmek elverişliydi, bu yüzden şu mantıklı geliyordu:

int main(int argc, char *argv[])

fakat bu denklik nedeniyle şöyle de yazabilirsiniz:

int main(int argc, char **argv)

Evet, bu tam anlamıyla bir pointer'a pointer'dır! Kolaylaştıracaksa, bunu bir string'e pointer olarak düşünün. Ama gerçekte, bir char gösteren bir değere pointer'dır.

Ayrıca şunların da eşdeğer olduğunu hatırlayın:

argv[i]
*(argv + i)

bu da argv üzerinde pointer aritmetiği yapabileceğiniz anlamına gelir.

Dolayısıyla komut satırı argümanlarını tüketmenin alternatif bir yolu, sondaki NULL değerine ulaşana kadar bir pointer'ı artırarak argv dizisinde ilerlemektir.

Toplama programımızı bunu yapacak şekilde değiştirelim:

#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv)
{
    int total = 0;
    
    // Derleyicinin kullanılmayan argc değişkeni hakkında
    // uyarı vermesini engellemek için sevimli bir numara:
    (void)argc;

    for (char **p = argv + 1; *p != NULL; p++) {
        int value = atoi(*p);  // Daha iyi hata yönetimi için strtol() kullanın

        total += value;
    }

    printf("%d\n", total);
}

Şahsen ben argv ögesine erişmek için dizi notasyonunu tercih ederim, ancak bu stilin de ortalıkta dolaştığını gördüm.

18.1.3 Eğlenceli Gerçekler

argc ve argv hakkında birkaç küçük şey daha.

  • Bazı ortamlar argv[0] değerini program adı olarak ayarlamayabilir. Mevcut değilse argv[0] boş bir string olacaktır. Bunun yaşandığını hiç görmedim.

  • Spesifikasyon, bir uygulamanın argv ile ne yapabileceği ve bu değerlerin nereden geldiği konusunda oldukça esnektir. Ancak bulunduğum her sistem, bu bölümde tartıştığımız şekilde çalışıyor.

  • argc, argv veya argv'nin işaret ettiği string'lerden herhangi birini değiştirebilirsiniz. (Yalnızca o string'leri mevcut uzunluklarından daha uzun hale getirmeyin!)

  • Bazı Unix benzeri sistemlerde, argv[0] string'ini değiştirmek ps komutunun çıktısının değişmesine neden olur122.

    Normalde ./foo ile çalıştırdığınız foo adlı bir programınız varsa, ps çıktısında şunu görebilirsiniz:

     4078 tty1     S      0:00 ./foo

    Ancak argv[0] ögesini yeni "Hi! " string'inin eski "./foo" ile aynı uzunlukta olmasına dikkat ederek şöyle değiştirirseniz:

    strcpy(argv[0], "Hi!  ");

    ve ardından ./foo programı hâlâ çalışırken ps komutunu çalıştırırsanız, yerine şunu görürüz:

     4079 tty1     S      0:00 Hi!

    Bu davranış spesifikasyonda yer almaz ve büyük ölçüde sisteme bağlıdır.

18.2 Çıkış Durumu

main() fonksiyon imzalarının dönüş türü olarak int kullandığını fark ettiniz mi? Bu neyle ilgilidir? Bu, programınızı başlatan programa işlerin nasıl gittiğini bildirmek için döndürülebilen bir tamsayı olan çıkış durumu (exit status) konusuyla ilgilidir.

C dilinde bir programın çıkış yapmasının, main() fonksiyonundan return ile dönmek veya exit() varyantlarından birini çağırmak da dahil olmak üzere birden fazla yolu vardır.

Bu yöntemlerin tümü argüman olarak bir int kabul eder.

Yan not: Neredeyse tüm örneklerimde main() fonksiyonunun bir int döndürmesi gerekmesine rağmen aslında hiçbir şey return etmediğimi gördünüz mü? Başka herhangi bir fonksiyonda bu yasa dışı olurdu, ancak C dilinde özel bir durum vardır: Kodun yürütülmesi bir return ile karşılaşmadan main() sonuna ulaşırsa, otomatik olarak return 0 yapar.

Peki 0 ne anlama gelir? Orada başka hangi sayıları kullanabiliriz? Ve bunlar nasıl kullanılır?

Spesifikasyon, yaygın olduğu üzere bu konuda hem net hem de muğlaktır. Net çünkü yapabileceklerinizi açıkça belirtir, ancak muğlak çünkü bunu özellikle sınırlandırmaz.

İleri atılıp bunu çözmekten başka çare yok!

Bir anlığına Inception123 moduna geçelim: Meğer programınızı çalıştırdığınızda, onu başka bir programdan çalıştırıyormuşsunuz.

Genellikle bu diğer program, başka programları başlatmak dışında kendi başına pek bir şey yapmayan bir tür kabuktur (shell)124.

Ancak bu, özellikle komut satırı kabuklarında belirgin olan çok aşamalı bir süreçtir:

  1. Kabuk programınızı başlatır
  2. Kabuk genellikle uyku moduna geçer (komut satırı kabukları için)
  3. Programınız çalışır
  4. Programınız sonlanır
  5. Kabuk uyanır ve başka bir komut bekler

Şimdi, 4. ve 5. adımlar arasında gerçekleşen küçük bir iletişim vardır: program kabuğun sorgulayabileceği bir durum değeri (status value) döndürebilir. Tipik olarak bu değer programınızın başarısını veya başarısızlığını ve eğer bir başarısızlık varsa ne tür bir başarısızlık olduğunu belirtmek için kullanılır.

Bu değer, main() fonksiyonundan return ile döndürdüğümüz şeydir. Durum odur.

C spesifikasyonu, <stdlib.h> içinde tanımlanmış makro adlarına sahip iki farklı durum değerine izin verir:

Durum Açıklama
EXIT_SUCCESS veya 0 Program başarıyla sonlandı.
EXIT_FAILURE Program bir hatayla sonlandı.

Komut satırından gelen iki sayıyı çarpan kısa bir program yazalım. Tam olarak iki değer belirtmenizi şart koşacağız. Belirtmezseniz bir hata mesajı yazdıracağız ve bir hata durumuyla çıkış yapacağız.

#include <stdio.h>
#include <stdlib.h>

int main(int argc, char **argv)
{
    if (argc != 3) {
        printf("usage: mult x y\n");
        return EXIT_FAILURE;   // Kabuğa işin yolunda gitmediğini bildir
    }

    printf("%d\n", atoi(argv[1]) * atoi(argv[2]));

    return 0;  // EXIT_SUCCESS ile aynı, her şey yolunda.
}

Şimdi bunu çalıştırmayı denersek, komut satırı argümanlarının sayısını tam olarak doğru belirtine kadar beklenen etkiyi elde ederiz:

$ ./mult
usage: mult x y

$ ./mult 3 4 5
usage: mult x y

$ ./mult 3 4
12

Ancak bu durum, döndürdüğümüz çıkış durumunu tam olarak göstermez, değil mi? Yine de kabuğun bunu yazdırmasını sağlayabiliriz. Bash veya başka bir POSIX kabuğu çalıştırdığınızı varsayarsak, bunu görmek için echo $? kullanabilirsiniz125.

Deneyelim:

$ ./mult
usage: mult x y
$ echo $?
1

$ ./mult 3 4 5
usage: mult x y
$ echo $?
1

$ ./mult 3 4
12
$ echo $?
0

İlginç! Benim sistemimde EXIT_FAILURE değerinin 1 olduğunu görüyoruz. Spesifikasyon bunu açıkça belirtmez, dolayısıyla herhangi bir sayı olabilir. Ama deneyin; sizin sisteminizde de büyük ihtimalle 1'dir.

18.2.1 Diğer Çıkış Durum Değerleri

0 durumu kesinlikle başarı anlamına gelir, peki ya diğer tüm tamsayılar, hatta negatif olanlar?

Burada C spesifikasyonunun dışına çıkıp Unix diyarına geçiyoruz. Genel olarak 0 başarı anlamına gelirken, sıfır olmayan pozitif bir sayı başarısızlık anlamına gelir. Yani yalnızca tek bir başarı türüne ve birden fazla başarısızlık türüne sahip olabilirsiniz. Bash çıkış kodunun 0 ile 255 arasında olması gerektiğini söyler, ancak bazı kodlar ayrılmıştır.

Özetle, Unix ortamında farklı hata çıkış durumlarını belirtmek istiyorsanız 1 ile başlayıp yukarı doğru ilerleyebilirsiniz.

Linux'ta, 0-255 aralığının dışındaki bir kodu denerseniz, kod üzerinde 0xff ile bit düzeyinde AND (bitwise AND) işlemi uygulayarak onu bu aralığa sabitler (clamp eder).

Bundan sonra ne yapılacağına karar vermek için bu durum kodlarını kullanacak şekilde kabuk betiği yazabilirsiniz.

18.3 Çevre Değişkenleri

Buna girmeden önce, C dilinin bir çevre değişkeninin ne olduğunu belirtmediği konusunda sizi uyarmalıyım. Bu yüzden bildiğim her büyük platformda çalışan çevre değişkeni sistemini anlatacağım.

Temelde çevre (environment), programınızı çalıştıracak olan programdır, örneğin bash kabuğu. Ve tanımlanmış bazı bash değişkenlerine sahip olabilir. Bilmiyorsanız söyleyeyim, kabuk kendi değişkenlerini oluşturabilir. Her kabuk farklıdır, ancak bash içinde sadece set yazabilirsiniz ve size hepsini gösterir.

İşte bash kabuğumda tanımlı olan 61 değişkenden bir kesit:

HISTFILE=/home/beej/.bash_history
HISTFILESIZE=500
HISTSIZE=500
HOME=/home/beej
HOSTNAME=FBILAPTOP
HOSTTYPE=x86_64
IFS=$' \t\n'

Bunların anahtar/değer (key/value) çiftleri şeklinde olduğuna dikkat edin. Örneğin bir anahtar HOSTTYPE ve değeri x86_64'tür. C perspektifinden bakıldığında, sayılar olsalar bile tüm değerler metin dizisidir (string)126.

Yani her neyse! Uzun lafın kısası, bu değerleri C programınızın içinden almak mümkündür.

Kabukta ayarladığınız bir değeri aramak için standart getenv() fonksiyonunu kullanan bir program yazalım.

getenv(), değer string'ine bir pointer döndürür veya çevre değişkeni mevcut değilse NULL döndürür.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    char *val = getenv("FROTZ");  // Değeri almaya çalış

    // Var olduğundan emin olmak için kontrol et
    if (val == NULL) {
        printf("Cannot find the FROTZ environment variable\n");
        return EXIT_FAILURE;
    }

    printf("Value: %s\n", val);
}

Bunu doğrudan çalıştırırsam şunu elde ederim:

$ ./foo
Cannot find the FROTZ environment variable

ki henüz ayarlamadığım için bu gayet mantıklıdır.

Bash'te onu bir şeye ayarlayabilirim127:

$ export FROTZ="C is awesome!"

Sonra çalıştırırsam şunu alırım:

$ ./foo
Value: C is awesome!

Bu şekilde çevre değişkenlerinde veri hazırlayabilir ve bunu C kodunuzda alarak davranışınızı buna göre değiştirebilirsiniz.

18.3.1 Çevre Değişkenlerini Ayarlamak

Bu standart değildir, ancak bir çok sistem çevre değişkenlerini ayarlamak için yollar sağlar.

Unix benzeri bir sistemdeyseniz putenv(), setenv() ve unsetenv() dokümantasyonuna bakın. Windows'ta _putenv() fonksiyonuna bakın.

18.3.2 Unix Benzeri Alternatif Çevre Değişkenleri

Unix benzeri bir sistemdeyseniz, çevre değişkenlerine erişmenin birkaç yoluna daha sahip olma ihtimaliniz yüksektir. Spesifikasyon bunun yaygın bir uzantı olduğunu belirtse de, C standardının tam olarak bir parçası olmadığını unutmayın. Bununla birlikte POSIX standardının bir parçasıdır.

Bunlardan biri şu şekilde bildirilmesi gereken environ adlı bir değişkendir:

extern char **environ;

Bu, NULL pointer ile sonlandırılmış bir string dizisidir.

Kullanmadan önce onu kendiniz bildirmelisiniz (declare etmelisiniz) veya standart dışı <unistd.h> başlık dosyasında bulabilirsiniz.

Her string "anahtar=değer" biçimindedir, dolayısıyla anahtarları ve değerleri çıkarmak istiyorsanız onu kendiniz bölmeli ve ayrıştırmalısınız.

İşte çevre değişkenleri arasında döngü kurmanın ve onları birkaç farklı yolla yazdırmanın bir örneği:

#include <stdio.h>

extern char **environ;  // extern OLMALI VE "environ" olarak adlandırılmalı

int main(void)
{
    for (char **p = environ; *p != NULL; p++) {
        printf("%s\n", *p);
    }

    // Veya şöyle de yapabilirsiniz:
    for (int i = 0; environ[i] != NULL; i++) {
        printf("%s\n", environ[i]);
    }
}

Şuna benzeyen bir sürü çıktı için:

SHELL=/bin/bash
COLORTERM=truecolor
TERM_PROGRAM_VERSION=1.53.2
LOGNAME=beej
HOME=/home/beej
... vb ...

Mümkünse getenv() kullanın çünkü daha taşınabilirdir (portable). Ancak çevre değişkenleri üzerinde gezinmeniz gerekiyorsa environ kullanmak izlenecek yol olabilir.

Çevre değişkenlerini almanın standart dışı bir başka yolu da main() fonksiyonuna bir parametre olarak almaktır. Neredeyse aynı şekilde çalışır, ancak extern environ değişkeninizi ekleme ihtiyacını ortadan kaldırırsınız. POSIX spesifikasyonu bile bunu desteklemez128 görebildiğim kadarıyla, ancak Unix diyarında yaygındır.

#include <stdio.h>

int main(int argc, char **argv, char **env)  // <-- env!
{
    (void)argc; (void)argv;  // Kullanılmayan değişken uyarılarını bastır

    for (char **p = env; *p != NULL; p++) {
        printf("%s\n", *p);
    }

    // Veya şöyle de yapabilirsiniz:
    for (int i = 0; env[i] != NULL; i++) {
        printf("%s\n", env[i]);
    }
}

Tıpkı environ kullanmak gibi ama daha da az taşınabilir. Hedeflerin olması güzeldir.
