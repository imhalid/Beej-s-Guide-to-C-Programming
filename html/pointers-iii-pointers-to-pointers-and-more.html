23 Pointer'lar III: Pointer'lara Pointer'lar ve Daha Fazlası

Burada bazı orta ve ileri düzey pointer kullanımlarını ele alıyoruz. Pointer konusunu henüz tam kavrayamadıysanız, bu konulara başlamadan önce pointer'lar ve pointer aritmetiği hakkındaki önceki bölümleri gözden geçirin.

23.1 Pointer'lara Pointer'lar

Bir değişkene işaret eden bir pointer'ınız olabiliyorsa ve bir değişken de bir pointer olabiliyorsa, kendisi de bir pointer olan bir değişkene işaret eden bir pointer'ınız olabilir mi?

Evet! Bu bir pointer'a işaret eden pointer'dır (pointer-to-pointer) ve pointer-pointer türündeki bir değişkende tutulur.

Buna daldırmadan önce, pointer'lara pointer'ların nasıl çalıştığına dair sezgisel bir his edinmenizi istiyorum.

Bir pointer'ın sadece bir sayı olduğunu unutmayın. Bilgisayar belleğindeki bir indeksi temsil eden bir sayıdır; genellikle bir nedenden ötürü ilgilendiğimiz bir değeri tutan bir adrestir.

Bir sayı olan o pointer'ın bir yerde saklanması gerekir. Ve o yer, diğer her şey gibi bellektir141.

Fakat bellekte saklandığı için, saklandığı bir indeks de olmalı, değil mi? Pointer'ın saklandığı bellekte bir indeksi olmalıdır. Ve bu indeks bir sayıdır. O, pointer'ın adresidir. Yani pointer'a işaret eden bir pointer'dır.

Önceki bölümlere dönüp bir int değişkenine işaret eden normal bir pointer ile başlayalım:

#include <stdio.h>

int main(void)
{
    int x = 3490;  // Tür: int
    int *p = &x;   // Tür: int'e pointer

    printf("%d\n", *p);  // 3490
}

Yeterince açık, değil mi? Temsil edilen iki türümüz var: int ve int*; ve p'yi x'i gösterecek şekilde ayarlıyoruz. Ardından 8. satırda p'nin değerini alabilir (dereference) ve 3490 değerini yazdırabiliriz.

Ancak söylediğimiz gibi, herhangi bir değişkene işaret eden bir pointer'ımız olabilir… yani bu p'ye işaret eden bir pointer'ımız olabileceği anlamına mı gelir?

Başka bir deyişle, bu ifadenin türü nedir?

int x = 3490;  // Tür: int
int *p = &x;   // Tür: int'e pointer

&p  // <-- p'nin adresi hangi türdedir? Yani p'ye işaret eden bir pointer?

Eğer x bir int ise, &x bir int pointer'ıdır ve bunu int* türündeki p içinde sakladık. Anlaşıldı mı? (Anlayana kadar bu paragrafı tekrar okuyun!)

Ve bu nedenle &p, bir int* pointer'ına işaret eder; yani "bir int pointer'ına işaret eden pointer". Yani "int-pointer-pointer".

Kavradınız mı? (Kavrayana kadar önceki paragrafı tekrarlayın!)

Bu türü iki yıldız işaretiyle yazarız: int **. Şimdi bunu eylem halinde görelim.

#include <stdio.h>

int main(void)
{
    int x = 3490;  // Tür: int
    int *p = &x;   // Tür: int'e pointer
    int **q = &p;  // Tür: int'e pointer'a pointer

    printf("%d %d\n", *p, **q);  // 3490 3490
}

Örnek olarak yukarıdaki değerler için uydurma bazı adresler oluşturalım ve bu üç değişkenin bellekte nasıl görünebileceğine bakalım. Aşağıdaki adres değerleri yalnızca örnek amacıyla tarafımdan uydurulmuştur:

Değişken Saklandığı Adres Orada Saklanan Değer
x 28350 3490—koddan gelen değer
p 29122 28350—x'in adresi!
q 30840 29122—p'nin adresi!

Nitekim, bunu bilgisayarımda gerçek olarak deneyelim142 ve %p ile pointer değerlerini yazdıralım; ben de gerçek referanslarla (onaltılık/hex olarak yazdırılmış) aynı tabloyu tekrar yapayım.

Değişken Saklandığı Adres Orada Saklanan Değer
x 0x7ffd96a07b94 3490—koddan gelen değer
p 0x7ffd96a07b98 0x7ffd96a07b94—x'in adresi!
q 0x7ffd96a07ba0 0x7ffd96a07b98—p'nin adresi!

Bu adreslerin son bayt haricinde aynı olduğunu görebilirsiniz, bu yüzden sadece onlara odaklanın.

Benim sistemimde int'ler 4 bayttır, bu yüzden adresin x'ten p'ye 4 arttığını143 ve ardından p'den q'ya 8 arttığını görüyoruz. Benim sistemimde tüm pointer'lar 8 bayttır.

int* veya int** olması fark eder mi? Biri diğerinden daha mı fazla bayttır? Hayır! Tüm pointer'ların adresler, yani bellekteki indeksler olduğunu unutmayın. Ve benim makinemde bir indeksi 8 bayt ile temsil edebilirsiniz… o indekste neyin saklandığı önemli değildir.

Şimdi önceki örneğin 9. satırında ne yaptığımıza bakın: 3490 değerimize geri dönmek için q'yu çifte dereference ettik (değerini iki kez çıkardık).

Pointer'lar ve pointer'lara pointer'lar hakkında önemli kısım şudur:

  • & ile herhangi bir şeyin pointer'ını alabilirsiniz (bir pointer dahil!)
  • * ile bir pointer'ın işaret ettiği şeyi alabilirsiniz (bir pointer dahil!)

Yani & işaretinin pointer oluşturmak için kullanıldığını, * işaretinin ise bunun tersi olduğunu—& işaretinin ters yönünde hareket ettiğini—ve işaret edilen şeye ulaşmayı sağladığını düşünebilirsiniz.

Tür açısından, her & kullandığınızda bu tür seviyesine yeni bir pointer katmanı ekler.

Elinizde bu varsa Bunu çalıştırdığınızda Sonuç türü şudur
int x &x int *
int *x &x int **
int **x &x int ***
int ***x &x int ****

Ve dereference (*) her kullandığınızda, bunun tersini yapar:

Elinizde bu varsa Bunu çalıştırdığınızda Sonuç türü şudur
int ****x *x int ***
int ***x *x int **
int **x *x int *
int *x *x int

Yukarıdaki **q örnek kodunda gördüğümüz gibi, hızlı bir şekilde dereference etmek için üst üste birden fazla * kullanabileceğinizi unutmayın. Her biri bir dolaylı erişim (indirection) seviyesini kaldırır.

Elinizde bu varsa Bunu çalıştırdığınızda Sonuç türü şudur
int ****x ***x int *
int ***x **x int *
int **x **x int

Genel olarak, &*E == E geçerlidir144. Dereference işlemi, adres alma (address-of) işlemini "geri alır".

Ancak & aynı şekilde çalışmaz—bunları yalnızca tek tek yapabilirsiniz ve sonucu ara bir değişkende saklamanız gerekir:

int x = 3490;     // Tür: int
int *p = &x;      // Tür: int *, int'e pointer
int **q = &p;     // Tür: int **, int'e pointer'a pointer
int ***r = &q;    // Tür: int ***, int'e pointer'a pointer'a pointer
int ****s = &r;   // Tür: int ****, fikri anladınız
int *****t = &s;  // Tür: int *****

23.1.1 Pointer Pointer'lar ve const

Hatırlayacağınız üzere, bir pointer'ı şu şekilde tanımlamak:

int *const p;

p'yi değiştiremeyeceğiniz anlamına gelir. p++ yapmaya çalışmak bir derleme zamanı hatası verir.

Peki bu int ** veya int *** ile nasıl çalışır? const nereye gider ve ne anlama gelir?

Basit kısımla başlayalım. Değişken adının hemen yanındaki const o değişkeni ifade eder. Bu yüzden değiştiremeyeceğiniz bir int*** istiyorsanız, şunu yapabilirsiniz:

int ***const p;

p++;  // İzin verilmez

Ancak işlerin biraz garipleştiği yer burasıdır.

Ya şöyle bir durumumuz olsaydı:

int main(void)
{
    int x = 3490;
    int *const p = &x;
    int **q = &p;
}

Bunu derlediğimde bir uyarı alıyorum:

warning: initialization discards ‘const’ qualifier from pointer target type
    7 |     int **q = &p;
      |               ^

Neler oluyor? Derleyici burada bize const olan bir değişkenimiz olduğunu ve değerini aynı şekilde const olmayan başka bir değişkene atadığımızı söylüyor. "const'luk" niteliği atılıyor ki bu muhtemelen yapmak istediğimiz şey değildir.

p'nin türü int *const p'dir, dolayısıyla &p türü int *const * olur. Ve bunu q içine atamaya çalışıyoruz.

Ancak q, int ** türündedir! İlk * üzerinde farklı bir const niteliğine sahip bir tür! Bu nedenle p'nin int *const * türündeki const niteliğinin göz ardı edildiği ve çöpe atıldığı konusunda bir uyarı alıyoruz.

q'nun türünün en az p kadar const olduğundan emin olarak bunu düzeltebiliriz.

int x = 3490;
int *const p = &x;
int *const *q = &p;

Ve şimdi mutluyuz.

q'yu daha da const yapabilirdik. Yukarıdaki haliyle, "q'nun kendisi const değil, ancak gösterdiği şey const" diyoruz. Ancak ikisini de const yapabiliriz:

int x = 3490;
int *const p = &x;
int *const *const q = &p;  // Daha fazla const!

Ve bu da çalışır. Artık q'yu veya q'nun işaret ettiği pointer'ı değiştiremeyiz.

23.2 Çoklu Bayt Değerler

Daha önce çeşitli yerlerde buna biraz değinmiştik, ancak açıktır ki her değer belleğin tek bir baytında saklanamaz. Nesneler bellekte birden fazla bayt kaplar (char olmadıkları varsayımıyla). sizeof kullanarak kaç bayt olduğunu anlayabilirsiniz. Ve her zaman ilk baytın adresini döndüren standart & operatörünü kullanarak bellekteki hangi adresin nesnenin ilk baytı olduğunu anlayabilirsiniz.

İşte eğlenceli bir bilgi daha! Herhangi bir nesnenin baytları üzerinde gezinirseniz, onun nesne temsilini (object representation) elde edersiniz. Bellekte aynı nesne temsiline sahip iki şey birbirine eşittir.

Nesne temsili üzerinde gezinmek istiyorsanız, bunu unsigned char pointer'ları ile yapmalısınız.

Tam da bunu yapan kendi memcpy()145 sürümümüzü oluşturalım:

void *my_memcpy(void *dest, const void *src, size_t n)
{
    // src ve dest için unsigned char türünde yerel değişkenler oluştur

    const unsigned char *s = src;
    unsigned char *d = dest;

    while (n-- > 0)   // Verilen bayt sayısı için
        *d++ = *s++;  // Kaynak baytı hedef bayta kopyala

    // Çoğu kopyalama fonksiyonu çağıran kişiye kolaylık olsun diye dest pointer'ı döndürür

    return dest;
}

(İncelemeniz için orada sonradan artırma (post-increment) ve sonradan azaltmaya (post-decrement) dair güzel örnekler de var.)

Yukarıdaki sürümün muhtemelen sisteminizle birlikte gelenden daha az verimli olduğunu unutmamak önemlidir.

Ancak içine herhangi bir şeyin pointer'ını geçirebilirsiniz ve o nesneleri kopyalar. int*, struct animal* veya herhangi bir şey olabilir.

İçinde herhangi bir dolgu baytı (padding) olup olmadığını ve hangi değerlere sahip olduğunu görebilmemiz için bir struct yapısının nesne temsil baytlarını yazdıran başka bir örnek yapalım146.

#include <stdio.h>

struct foo {
    char a;
    int b;
};

int main(void)
{
    struct foo x = {0x12, 0x12345678};
    unsigned char *p = (unsigned char *)&x;

    for (size_t i = 0; i < sizeof x; i++) {
        printf("%02X\n", p[i]);
    }
}

Burada elimizde bir derleyiciyi dolgu baytları (padding) eklemeye teşvik edecek şekilde inşa edilmiş bir struct foo var (eklemek zorunda olmasa da). Ve ardından struct foo türündeki x değişkeninin ilk baytına işaret eden bir unsigned char * alıyoruz.

Oradan itibaren tek bilmemiz gereken sizeof x değeridir ve o kadar bayt boyunca döngü kurup değerleri (kolaylık olsun diye hex olarak) yazdırabiliriz.

Bunu çalıştırmak çıktı olarak bir sürü sayı verir. Değerlerin nerede saklandığını belirlemek için aşağıda açıklama ekledim:

12  | x.a == 0x12

AB  |
BF  | "rastgele" değerli dolgu baytları (padding)
26  |

78  | x.b == 0x12345678
56  |
34  |
12  |

Tüm sistemlerde sizeof(char) 1'dir ve çıktının en üstünde oraya sakladığımız 0x12 değerini tutan ilk baytı görürüz.

Ardından bazı dolgu baytları var—bende bunlar çalıştırılmadan çalıştırılmaya değişti.

Son olarak benim sistemimde sizeof(int) 4'tür ve sondaki o 4 baytı görebiliriz. 0x12345678 hex değerindeki baytlarla aynı olduklarına, ancak garip bir şekilde ters sırada olduklarına dikkat edin147.

Bu, bellekteki daha karmaşık bir yapının baytlarına kaputun altından küçük bir bakıştır.

23.3 NULL Pointer ve Sıfır

Şu ögeler birbirinin yerine kullanılabilir:

  • NULL
  • 0
  • '\0'
  • (void *)0

Şahsen ben NULL kastettiğimde her zaman NULL kullanırım, ancak zaman zaman başka varyantlar da görebilirsiniz. '\0' (tüm bitleri sıfır olan bir bayt) eşitlik karşılaştırmasında doğru çıksa da, onu bir pointer ile karşılaştırmak gariptir; pointer ile NULL karşılaştırmalısınız. (Elbette metin işleme yaparken çoğu zaman pointer'ın gösterdiği şeyi '\0' ile karşılaştırırsınız ki bu doğrudur.)

0 değerine boş gösterici sabiti (null pointer constant) denir ve başka bir pointer ile karşılaştırıldığında veya atandığında, aynı türden bir boş göstericiye (null pointer) dönüştürülür.

23.4 Tam Sayı Olarak Pointer'lar

Pointer'ları tam sayılara ve tam tersine tür dönüşümüne (cast) tabi tutabilirsiniz (çünkü bir pointer yalnızca bellekteki bir indekstir), ancak muhtemelen yalnızca bazı alt seviye donanım işleri yapıyorsanız buna ihtiyaç duyarsınız. Bu tür işlemlerin sonuçları uygulamaya bağlı davranıştır (implementation-defined), dolayısıyla taşınabilir değildir. Ve garip şeyler yaşanabilir.

Yine de C bir garanti verir: bir pointer'ı uintptr_t türüne dönüştürebilir ve herhangi bir veri kaybetmeden tekrar bir pointer'a dönüştürebilirsiniz.

uintptr_t, <stdint.h> içinde tanımlanmıştır148.

Ayrıca, işaretli (signed) kullanmak isterseniz, aynı etki için intptr_t kullanabilirsiniz.

23.5 Pointer'ları Başka Pointer'lara Dönüştürmek (Cast)

Yalnızca tek bir güvenli pointer dönüşümü vardır:

  1. intptr_t veya uintptr_t türüne dönüştürmek.
  2. void* türüne ve türünden dönüştürmek.

İKİ! İki güvenli pointer dönüşümü.

  1. char* (veya signed char*/unsigned char*) türüne ve türünden dönüştürmek.

ÜÇ! Üç güvenli dönüşüm!

  1. Bir struct pointer'ından ilk üyesinin pointer'ına ve tam tersine dönüştürmek.

DÖRT! Dört güvenli dönüşüm!

Başka bir türün pointer'ına dönüşüm yapıp ardından gösterdiği nesneye erişirseniz, kesin takma adlandırma (strict aliasing) adı verilen bir şey nedeniyle davranış tanımsızdır (undefined behavior).

Sade aliasing (takma adlandırma), aynı nesneye erişmek için birden fazla yola sahip olma yeteneğini ifade eder. Erişim noktaları birbirinin takma adıdır (alias).

Strict aliasing, bir nesneye yalnızca o nesneyle uyumlu türdeki pointer'lar aracılığıyla erişmenize izin verildiğini söyler.

Örneğin, buna kesinlikle izin verilir:

int a = 1;
int *p = &a;

p bir int pointer'ıdır ve uyumlu bir türü—yani int—gösterir, dolayısıyla harikayız.

Ancak aşağıdakisi iyi değildir çünkü int ve float uyumlu türler değildir:

int a = 1;
float *p = (float *)&a;

İşte aliasing yapan bir gösteri programı. int32_t türündeki bir v değişkenini alır ve onu bir struct words pointer'ına takma ad olarak bağlar. O struct içinde iki adet int16_t barındırır. Bu türler uyumsuzdur, dolayısıyla strict aliasing kurallarını ihlal ediyoruz. Derleyici bu iki pointer'ın asla aynı nesneyi göstermediğini varsayacaktır… ama biz ikisinin de aynı yeri göstermesini sağlıyoruz. Ki bu yaramaz bir davranıştır.

Gelin bir şeyleri bozup bozamayacağımıza bakalım.

#include <stdio.h>
#include <stdint.h>

struct words {
    int16_t v[2];
};

void fun(int32_t *pv, struct words *pw)
{
    for (int i = 0; i < 5; i++) {
        (*pv)++;

        // 32-bitlik değeri ve 16-bitlik değerleri yazdır:

        printf("%x, %x-%x\n", *pv, pw->v[1], pw->v[0]);
    }
}

int main(void)
{
    int32_t v = 0x12345678;

    struct words *pw = (struct words *)&v;  // Strict aliasing kuralını ihlal eder

    fun(&v, pw);
}

fun() fonksiyonuna iki uyumsuz pointer'ı nasıl geçirdiğimi gördünüz mü? Türlerden biri int32_t*, diğeri ise struct words*.

Ancak ikisi de aynı nesneyi gösterir: 0x12345678 olarak ilklendirilmiş 32-bitlik değer.

Yani struct words içindeki alanlara bakarsak, o sayının 16-bitlik iki yarısını görmeliyiz. Değil mi?

Ve fun() döngüsünde int32_t pointer'ını artırıyoruz. Bu kadar. Ancak struct aynı belleği gösterdiğinden, o da aynı değere güncellenmelidir.

O halde çalıştıralım ve sol tarafta 32-bitlik değer ve sağ tarafta 16-bitlik iki kısım olacak şekilde bunu elde edelim. Eşleşmesi gerekir149:

12345679, 1234-5679
1234567a, 1234-567a
1234567b, 1234-567b
1234567c, 1234-567c
1234567d, 1234-567d

ve eşleşir… YARINA KADAR!

GCC'yi -O3 ve -fstrict-aliasing ile derlemeyi deneyelim:

12345679, 1234-5678
1234567a, 1234-5679
1234567b, 1234-567a
1234567c, 1234-567b
1234567d, 1234-567c

Bir farkla kaçıyorlar! Ama aynı belleği gösteriyorlar! Bu nasıl olabilir? Cevap: Belleği bu şekilde takma adlandırmak tanımsız davranıştır (undefined behavior). Her şey mümkündür, ancak iyi anlamda değil.

Kodunuz strict aliasing kurallarını ihlal ediyorsa, çalışıp çalışmaması birinin onu nasıl derlemeye karar verdiğine bağlıdır. Ve bu sizin kontrolünüz dışında olduğu için can sıkıcıdır. Tabii her şeye gücü yeten bir ilah değilseniz.

Pek olası değil, üzgünüm.

GCC, -fno-strict-aliasing bayrağı ile strict aliasing kurallarını kullanmamaya zorlanabilir. Yukarıdaki gösteri programını -O3 ve bu bayrakla derlemek, çıktının beklendiği gibi olmasına neden olur.

Son olarak, type punning (tür manipülasyonu), aynı veriye bakmak için farklı türdeki pointer'ları kullanmaktır. Strict aliasing öncesinde bu tür şeyler oldukça yaygındı:

int a = 0x12345678;
short b = *((short *)&a);   // Strict aliasing kuralını ihlal eder

Type punning işlemini (nispeten) güvenli bir şekilde yapmak istiyorsanız, Union'lar ve Type Punning bölümüne bakın.

23.6 Pointer Farkları

Pointer aritmetiği bölümünden bildiğiniz gibi, dizi eleman sayısı cinsinden aralarındaki farkı bulmak için bir pointer'ı diğerinden çıkarabilirsiniz150.

Şimdi o farkın türü uygulamaya bağlı (implementation) bir şeydir, bu yüzden sistemden sisteme değişebilir.

Daha taşınabilir olması için sonucu <stddef.h> içinde tanımlanan ptrdiff_t türünde bir değişkende saklayabilirsiniz.

int cats[100];

int *f = cats + 20;
int *g = cats + 60;

ptrdiff_t d = g - f;  // fark 40'tır

Ve tam sayı format belirtecinin önüne t ekleyerek bunu yazdırabilirsiniz:

printf("%td\n", d);  // Onluk tabanda yazdır: 40
printf("%tX\n", d);  // Hex tabanında yazdır:   28

23.7 Fonksiyon Pointer'ları

Fonksiyonlar bellekteki makine talimatları koleksiyonudur, bu nedenle fonksiyonun ilk talimatına bir pointer alamamamız için hiçbir neden yoktur.

Ve ardından onu çağırabiliriz.

Bu, bir fonksiyona pointer'ı başka bir fonksiyona argüman olarak geçirmek için yararlı olabilir. Böylece ikincisi içine geçirilen neyse onu çağırabilir.

Ancak bunlarla ilgili çetrefilli kısım, C'nin fonksiyona işaret eden pointer değişkeninin türünü bilmesinin gerekmesidir.

Ve tüm detayları gerçekten bilmek ister.

"Bu, iki int argümanı alan ve void döndüren bir fonksiyona işaret eden pointer'dır" gibi.

Bir değişken tanımlayabilmek için tüm meblağı nasıl yazarsınız?

Görünüşe göre, bazı ekstra parantezler dışında bir fonksiyon prototipine çok benziyor:

// p'yi bir fonksiyon pointer'ı olarak tanımla.
// Bu fonksiyon float döndürür ve argüman olarak iki int alır.

float (*p)(int, int);

Ayrıca parametrelere isim vermek zorunda olmadığınıza da dikkat edin. Ancak isterseniz verebilirsiniz; sadece göz ardı edilirler.

// p'yi bir fonksiyon pointer'ı olarak tanımla.
// Bu fonksiyon float döndürür ve argüman olarak iki int alır.

float (*p)(int a, int b);

Şimdi bir değişkeni nasıl tanımlayacağımızı bildiğimize göre, içine ne atayacağımızı nasıl biliriz? Bir fonksiyonun adresini nasıl alırız?

Bir dizinin pointer'ını almaya benzer bir kısayol olduğu ortaya çıkıyor: parantezler olmadan sadece yalın fonksiyon adına başvurabilirsiniz. (İsterseniz önüne bir & koyabilirsiniz, ancak bu gereksizdir ve deyimsel/idiomatic değildir.)

Bir fonksiyon pointer'ına sahip olduğunuzda, sadece parantezler ve bir argüman listesi ekleyerek onu çağırabilirsiniz.

Bir fonksiyona pointer ayarlayarak ona etkili bir şekilde takma ad (alias) oluşturduğum basit bir örnek yapalım. Ardından onu çağıracağız.

Bu kod 3490 yazdırır:

#include <stdio.h>

void print_int(int n)
{
    printf("%d\n", n);
}

int main(void)
{
    // p'yi print_int'i gösterecek şekilde ata:

    void (*p)(int) = print_int;

    p(3490);          // Pointer aracılığıyla print_int'i çağır
}

p türünün print_int'in dönüş değerini ve parametre türlerini nasıl temsil ettiğine dikkat edin. Temsil etmek zorundadır, aksi takdirde C uyumsuz pointer türleri hakkında şikayet eder.

Buradaki bir başka örnek, bir fonksiyona işaret eden pointer'ı başka bir fonksiyona nasıl argüman olarak geçirebileceğimizi gösteriyor.

Birkaç tam sayı argümanı ve bu iki argüman üzerinde işlem yapan bir fonksiyon pointer'ı alan bir fonksiyon yazacağız. Ardından sonucu yazdırır.

#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

int mult(int a, int b)
{
    return a * b;
}

void print_math(int (*op)(int, int), int x, int y)
{
    int result = op(x, y);

    printf("%d\n", result);
}

int main(void)
{
    print_math(add, 5, 7);   // 12
    print_math(mult, 5, 7);  // 35
}

Bunu sindirmek için bir dakikanızı ayırın. Buradaki fikir, print_math() fonksiyonuna bir fonksiyon pointer'ı geçirecek olmamız ve onun da bazı matematiksel işlemler yapmak için o fonksiyonu çağıracak olmasıdır.

Bu şekilde içine başka bir fonksiyon geçirerek print_math() davranışını değiştirebiliriz. 22-23. satırlarda sırasıyla add ve mult fonksiyonlarının pointer'larını geçirdiğimizde bunu yaptığımızı görebilirsiniz.

Şimdi, 13. satırda, sanırım hepimiz print_math() fonksiyon imzasının görülmeye değer bir manzara olduğu konusunda hemfikiriz. Ve inanırsanız, bu aslında inşa edebileceğiniz bazı şeylere kıyasla oldukça anlaşılırdır151.

Fakat gelin bunu sindirelim. Görünüşe göre yalnızca üç parametre var, ancak bunları görmek biraz zor:

//                      op             x      y
//              |-----------------|  |---|  |---|
void print_math(int (*op)(int, int), int x, int y)

İlki, op, argüman olarak iki int alan ve bir int döndüren bir fonksiyona işaret eden pointer'dır. Bu hem add() hem de mult() imzalarıyla eşleşir.

İkinci ve üçüncü, x ve y, yalnızca standart int parametreleridir.

Çalışan parçaları tespit ederken gözlerinizi yavaşça ve bilinçli bir şekilde imzanın üzerinde gezdirin. Benim için her zaman öne çıkan şey (*op)( dizilimi, parantezler ve yıldız işaretidir. Bunun bir fonksiyon pointer'ı olduğunu ele veren şey budur.
