31 goto

goto ifadesi evrensel olarak el üstünde tutulur ve burada tartışmasız bir şekilde sunulabilir.

Şaka yapıyorum! Yıllar boyunca, goto kullanımının zararlı kabul edilip edilmeyeceği176 üzerine (çoğunlukla zararlı olduğu yönünde) çok fazla tartışma yapılmıştır.

Bu programcının fikrine göre, bakımı kolaylık ve hızı göz önünde bulundurarak en iyi koda ulaştıran hangi yapıysa onu kullanmalısınız. Ve bazen bu yapı goto olabilir!

Bu bölümde goto yapısının C'de nasıl çalıştığını göreceğiz ve ardından yaygın olarak kullanıldığı bazı durumlara göz atacağız177.

31.1 Basit Bir Örnek

Bu örnekte, bir kod satırını atlamak ve bir etikete (label) atlamak için goto kullanacağız. Etiket, bir goto hedefi olabilen tanımlayıcıdır—sonunda iki nokta üst üste (:) bulunur.

#include <stdio.h>

int main(void)
{
    printf("One\n");
    printf("Two\n");

    goto skip_3;

    printf("Three\n");

skip_3:

    printf("Five!\n");
}

Çıktı şöyledir:

One
Two
Five!

goto, aradaki her şeyi atlayarak yürütmeyi belirtilen etikete atlatır.

goto ile ileriye veya geriye atlayabilirsiniz.

infinite_loop:
    print("Hello, world!\n");
    goto infinite_loop;

Etiketler yürütme sırasında atlanır. Aşağıdaki kod, sanki etiketler hiç yokmuş gibi üç sayıyı da sırayla yazdıracaktır:

    printf("Zero\n");
label_1:
label_2:
    printf("One\n");
label_3:
    printf("Two\n");
label_4:
    printf("Three\n");

Fark ettiğiniz üzere, etiketleri en sola hizalamak yaygın bir kuraldır. Bu, okuyucunun hedefi bulmak için hızlıca göz gezdirmesini kolaylaştırarak okunabilirliği artırır.

Etiketler fonksiyon kapsamına (function scope) sahiptir. Yani, blokların ne kadar derininde görünürlerse görünsünler, fonksiyondaki herhangi bir yerden onlara goto yapabilirsiniz.

Bu aynı zamanda yalnızca goto ifadesiyle aynı fonksiyonda bulunan etiketlere goto yapabileceğiniz anlamına gelir. Başka fonksiyonlardaki etiketler goto açısından kapsam dışındadır. Ve aynı etiket adını iki farklı fonksiyonda kullanabileceğiniz—ancak aynı fonksiyonda aynı etiket adını kullanamayacağınız—anlamına gelir.

31.2 Etiketli continue

Bazı dillerde, bir continue ifadesi için aslında bir etiket belirtebilirsiniz. C buna izin vermez, ancak bunun yerine goto ifadesini kolayca kullanabilirsiniz.

Sorunu göstermek için, bu iç içe döngüdeki continue ifadesine göz atın:

for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        printf("%d, %d\n", i, j);
        continue;   // Her zaman bir sonraki j'ye gider
    }
}

Gördüğümüz gibi, bu continue, tüm continue ifadeleri gibi en içteki kapsayan döngünün bir sonraki yinelemesine gider. Peki ya bir dıştaki döngüde, yani i döngüsünde continue yapmak istersek?

Peki, dış döngüye geri dönmek için break kullanabiliriz, değil mi?

for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        printf("%d, %d\n", i, j);
        break;     // Bizi i'nin bir sonraki yinelemesine ulaştırır
    }
}

Bu bize iki seviyeli iç içe döngü olanağı sağlar. Ancak bir döngü daha iç içe koyarsak, seçeneklerimiz tükenir. Bizi i'nin bir sonraki yinelemesine ulaştıracak hiçbir ifademizin olmadığı şu duruma ne dersiniz?

for (int i = 0; i < 3; i++) {
    for (int j = 0; j < 3; j++) {
        for (int k = 0; k < 3; k++) {
            printf("%d, %d, %d\n", i, j, k);

            continue;  // Bizi k'nin bir sonraki yinelemesine ulaştırır
            break;     // Bizi j'nin bir sonraki yinelemesine ulaştırır
            ????;      // Bizi i'nin bir sonraki yinelemesine mi ulaştırır???

        }
    }
}

goto ifadesi bize bir yol sunar!

    for (int i = 0; i < 3; i++) {
        for (int j = 0; j < 3; j++) {
            for (int k = 0; k < 3; k++) {
                printf("%d, %d, %d\n", i, j, k);

                goto continue_i;   // Şimdi i döngüsüne devam ediyor!!
            }
        }
continue_i: ;
    }

Orada sonda bir ; var—bunun nedeni, bir bileşik ifadenin (compound statement) tam sonunu gösteren (veya bir değişken bildiriminden önce gelen) bir etiketinizin olamamasıdır.

31.3 Erken Çıkış Yapmak

Bazı kodların ortasında son derece derine yuvalanmış durumdayken, daha fazla if iç içe koymaktan ve bayrak değişkenleri kullanmaktan genellikle daha temiz bir yöntemle dışarı çıkmak için goto kullanabilirsiniz.

    // Sözde kod

    for(...) {
        for (...) {
            while (...) {
                do {
                    if (some_error_condition)
                        goto bail;

                } while(...);
            }
        }
    }

bail:
    // Temizlik işlemi burada

goto olmadan, tamamen dışarı çıkmak için tüm döngülerde bir hata durumu bayrağını kontrol etmeniz gerekirdi.

31.4 Etiketli break

Bu, continue ifadesinin yalnızca en içteki döngüyü sürdürmesine çok benzer bir durumdur. break de yalnızca en içteki döngüden çıkar.

    for (int i = 0; i < 3; i++) {
        for (int j = 0; j < 3; j++) {
            printf("%d, %d\n", i, j);
            break;   // Yalnızca j döngüsünden çıkar
        }
    }

    printf("Done!\n");

Ancak daha uzağa kırıp çıkmak için goto kullanabiliriz:

    for (int i = 0; i < 3; i++) {
        for (int j = 0; j < 3; j++) {
            printf("%d, %d\n", i, j);
            goto break_i;   // Şimdi i döngüsünden çıkıyor!
        }
    }

break_i:

    printf("Done!\n");

31.5 Çok Seviyeli Temizlik

Birden fazla sistemi başlatmak (initialize) için birden fazla fonksiyon çağırıyorsanız ve bunlardan biri başarısız olursa, yalnızca o ana kadar başlattığınız sistemleri kapatmalı/temizlemelisiniz.

Sistemleri başlatmaya başlayıp herhangi birinin hata döndürüp döndürmediğini kontrol ettiğimiz sahte bir örnek yapalım (bir hatayı belirtmek için -1 kullanacağız). Bunlardan biri hata döndürürse, yalnızca o ana kadar başlattığımız sistemleri kapatmamız gerekir.

    if (init_system_1() == -1)
        goto shutdown;

    if (init_system_2() == -1)
        goto shutdown_1;

    if (init_system_3() == -1)
        goto shutdown_2;

    if (init_system_4() == -1)
        goto shutdown_3;

    do_main_thing();   // Programımızı çalıştır

    shutdown_system4();

shutdown_3:
    shutdown_system3();

shutdown_2:
    shutdown_system2();

shutdown_1:
    shutdown_system1();

shutdown:
    print("All subsystems shut down.\n");

Alt sistemleri başlattığımız sıranın tersi sırayla kapattığımıza dikkat edin. Yani alt sistem 4 başlatılamazsa, sırasıyla 3, 2 ve 1'i kapatacaktır.

31.6 Kuyruk Çağrısı Optimizasyonu

Bir nevi. Yalnızca özyinelemeli (recursive) fonksiyonlar için.

Aşina değilseniz, Kuyruk Çağrısı Optimizasyonu (Tail Call Optimization - TCO)178 çok belirli koşullar altında diğer fonksiyonları çağırırken yığın (stack) alanını israf etmemenin bir yoludur. Ne yazık ki detaylar bu rehberin kapsamı dışındadır.

Ancak bu şekilde optimize edilebileceğini bildiğiniz özyinelemeli bir fonksiyonunuz varsa, bu teknikten yararlanabilirsiniz. (Etiketlerin fonksiyon kapsamı nedeniyle diğer fonksiyonlara kuyruk çağrısı yapamayacağınızı unutmayın.)

Basit bir örnek yapalım: Faktöriyel.

İşte TCO olmayan özyinelemeli bir sürüm, ancak TCO yapılabilir!

#include <stdio.h>
#include <complex.h>

int factorial(int n, int a)
{
    if (n == 0)
        return a;

    return factorial(n - 1, a * n);
}

int main(void)
{
    for (int i = 0; i < 8; i++)
        printf("%d! == %ld\n", i, factorial(i, 1));
}

Bunu gerçekleştirmek için çağrıyı iki adımla değiştirebilirsiniz:

  1. Parametrelerin değerlerini bir sonraki çağrıda olacakları değerlere ayarlayın.
  2. Fonksiyonun ilk satırındaki bir etikete goto ile atlayın.

Deneyelim:

#include <stdio.h>

int factorial(int n, int a)
{
tco:  // bunu ekleyin

    if (n == 0)
        return a;

    // return ifadesini yeni parametre değerlerini ayarlayarak ve
    // fonksiyonun başına goto yaparak değiştirin

    //return factorial(n - 1, a * n);

    int next_n = n - 1;  // Bunların yukarıdaki özyinelemeli argümanlarla nasıl
    int next_a = a * n;  // uyuştuğunu gördünüz mü?

    n = next_n;   // Parametreleri yeni değerlere ayarlayın
    a = next_a;

    goto tco;   // Ve tekrarlayın!
}

int main(void)
{
    for (int i = 0; i < 8; i++)
        printf("%d! == %d\n", i, factorial(i, 1));
}

Fonksiyonun başına atlamadan önce parametrelerin sonraki değerlerini ayarlamak için yukarıda geçici değişkenler kullandım. Yukarıdaki özyinelemeli çağrıda bulunan özyinelemeli argümanlara nasıl karşılık geldiklerini gördünüz mü?

Peki, neden geçici değişkenler kullanıyoruz? Bunun yerine şunu da yapabilirdim:

    a *= n;
    n -= 1;

    goto tco;

ve bu aslında gayet iyi çalışır. Ancak bu iki kod satırını dikkatsizce tersine çevirirsem:

    n -= 1;  // KÖTÜ HABER
    a *= n;

—şimdi başımız dertte. n değişkenini a değişkenini değiştirmek için kullanmadan önce değiştirdik. Bu kötüdür çünkü özyinelemeli çağrı yaptığınızda işler böyle yürümez. Geçici değişkenler kullanmak, dikkat etmiyor olsanız bile bu sorunu önler. Ve derleyici muhtemelen onları yine de optimize ederek kaldırır.

31.7 Kesintiye Uğrayan Sistem Çağrılarını Yeniden Başlatma

Bu, standart C spesifikasyonunun dışındadır, ancak Unix benzeri sistemlerde sıklıkla görülür.

Belirli uzun süreli sistem çağrıları (system calls), bir sinyalle kesintiye uğrarlarsa bir hata döndürebilir ve sistem çağrısının sorunsuz çalıştığını, yalnızca kesintiye uğradığını belirtmek için errno değeri EINTR olarak ayarlanır.

Bu durumlarda, programcının çağrıyı yeniden başlatması ve tekrar denemesi çok yaygındır.

retry:
    byte_count = read(0, buf, sizeof(buf) - 1);  // Unix read() sistem çağrısı

    if (byte_count == -1) {            // Bir hata oluştu...
        if (errno == EINTR) {          // Ama yalnızca kesintiye uğradı
            printf("Restarting...\n");
            goto retry;
        }

Birçok Unix benzeri sistemde, işletim sisteminin EINTR ile başarısız olmak yerine yavaş sistem çağrılarını otomatik olarak yeniden başlatmasını istemek için sigaction() fonksiyonuna geçirebileceğiniz bir SA_RESTART bayrağı vardır.

Yine, bu Unix'e özgüdür ve C standardının dışındadır.

Bununla birlikte, herhangi bir fonksiyonun yeniden başlatılması gerektiğinde benzer bir tekniği kullanmak mümkündür.

31.8 goto ve İzlek Öncelikleme (Thread Preemption)

Bu örnek doğrudan, kaliteli kitapların ücretsiz indirilebilir olması gerektiğine inanan benzer düşünen yazarların bir başka mükemmel kitabı olan Operating Systems: Three Easy Pieces kitabından alınmıştır. Fikirlerimi belli ettiğimden falan değil tabii.

retry:

    pthread_mutex_lock(L1);

    if (pthread_mutex_trylock(L2) != 0) {
        pthread_mutex_unlock(L1);
        goto retry;
    }

    save_the_day();

    pthread_mutex_unlock(L2);
    pthread_mutex_unlock(L1);

Burada izlek (thread) mutlu bir şekilde L1 mutex'ini alır, ancak daha sonra L2 mutex'i ile korunan ikinci kaynağı elde etmede potansiyel olarak başarısız olur (örneğin işbirliği yapmayan başka bir izlek onu elinde tutuyorsa). İzleğimiz L2 kilidini alamazsa, L1 kilidini açar ve ardından temiz bir şekilde yeniden denemek için goto kullanır.

Kahraman izleğimizin sonunda her iki mutex'i de elde etmeyi başaracağını ve kötü ölümcül kilitlenmelerden (deadlock) kaçınırken günü kurtaracağını umuyoruz.

31.9 goto ve Değişken Kapsamı

Etiketlerin fonksiyon kapsamına sahip olduğunu zaten gördük, ancak bazı değişken başlatmalarını atlarsak garip şeyler olabilir.

x değişkeninin kapsam dışında olduğu bir yerden, kapsamının ortasına (blok içine) atladığımız bu örneğe bakın.

    goto label;

    {
        int x = 12345;

label:
        printf("%d\n", x);
    }

Bu derlenecek ve çalışacaktır, ancak bana bir uyarı verir:

warning: ‘x’ is used uninitialized in this function

Ve ardından çalıştırdığımda 0 yazdırır (sizde farklılık gösterebilir).

Temel olarak gerçekleşen şey, x'in kapsamına atlamış olmamızdır (bu yüzden printf() içinde ona başvurmak sorun teşkil etmedi) ancak onu aslında 12345 olarak başlatan satırın üzerinden atladık. Dolayısıyla değer belirsizdi.

Çözüm elbette, şu ya da bu şekilde başlatmayı etiketten sonraya almaktır.

    goto label;

    {
        int x;

label:
        x = 12345;
        printf("%d\n", x);
    }

Bir örneğe daha bakalım.

    {
        int x = 10;

label:

        printf("%d\n", x);
    }

    goto label;

Burada ne olur?

Bloğa ilk girişte sorun yoktur. x değeri 10'dur ve yazdırılan da budur.

Ancak goto sonrasında, x'in kapsamına atlıyoruz, ancak ilk değer atamasının ötesine atlıyoruz. Bu da onu hala yazdırabileceğimiz, ancak değerin belirsiz olduğu anlamına gelir (çünkü yeniden başlatılmamıştır).

Benim makinemde yine 10 yazdırıyor (sonsuza kadar), ama bu sadece şans. goto sonrasında x başlatılmamış olduğu için herhangi bir değer yazdırabilir.

31.10 goto ve Değişken Uzunluklu Diziler

VLA'lar ve goto söz konusu olduğunda tek bir kural vardır: Bir VLA'nın kapsamının dışından o VLA'nın kapsamının içine atlayamazsınız.

Bunu yapmaya çalışırsam:

    int x = 10;

    goto label;

    {
        int v[x];

label:

        printf("Hi!\n");
    }

Bir hata alırım:

error: jump into scope of identifier with variably modified type

VLA bildiriminden önceye şu şekilde atlayabilirsiniz:

    int x = 10;

    goto label;

    {
label:  ;
        int v[x];

        printf("Hi!\n");
    }

Çünkü bu sayede VLA, kapsam dışına çıktığında kaçınılmaz olarak bellekten serbest bırakılmadan önce düzgün bir şekilde tahsis edilir.
