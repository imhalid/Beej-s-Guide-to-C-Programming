25 Değişken Sayıda Argüman Alan Fonksiyonlar (Variadic Functions)

Variadic (değişken sayıda argüman alan), rastgele sayıda argüman kabul eden fonksiyonlar için kullanılan havalı bir kelimedir.

Normal bir fonksiyon belirli sayıda argüman alır, örneğin:

int add(int x, int y)
{
    return x + y;
}

Bunu yalnızca x ve y parametrelerine karşılık gelen tam olarak iki argümanla çağırabilirsiniz.

add(2, 3);
add(5, 12);

Ancak daha fazlasıyla denerseniz, derleyici buna izin vermeyecektir:

add(2, 3, 4);  // HATA
add(5);        // HATA

Değişken argümanlı (variadic) fonksiyonlar bu kısıtlamayı bir dereceye kadar aşarlar.

Bunun ünlü bir örneğini printf() fonksiyonunda zaten görmüştük! Ona her türlü şeyi geçirebilirsiniz.

printf("Hello, world!\n");
printf("The number is %d\n", 2);
printf("The number is %d and pi is %f\n", 2, 3.14159);

Ona kaç tane argüman verdiğinizi umursamıyor gibi görünüyor!

Şey, bu tamamen doğru değil. Sıfır argüman vermek size bir hata verecektir:

printf();  // HATA

Bu bizi C dilindeki variadic fonksiyonların kısıtlamalarından birine götürür: en az bir argümana sahip olmalıdırlar.

Ancak bunun haricinde oldukça esnektirler, hatta tıpkı printf() fonksiyonunun yaptığı gibi argümanların farklı türlere sahip olmasına bile izin verirler.

Nasıl çalıştıklarını görelim!

25.1 Fonksiyon İmzalarında Üç Nokta (Ellipses)

Peki sözdizimsel (syntactically) olarak nasıl çalışır?

Yapacağınız şey, önce geçirilmesi zorunlu olan tüm argümanları koymaktır (ve en az bir tane olması gerektiğini unutmayın) ve bundan sonra ... koyarsınız. Tıpkı şöyle:

void func(int a, ...)   // Kelimenin tam anlamıyla burada 3 nokta var

Bunu gösteren bazı kodlar:

#include <stdio.h>

void func(int a, ...)
{
    printf("a is %d\n", a);  // "a is 2" yazdırır
}

int main(void)
{
    func(2, 3, 4, 5, 6);
}

Harika, a değişkenindeki o ilk argümanı alabiliyoruz, peki ya diğer argümanlar? Onlara nasıl ulaşırsınız?

Eğlence işte burada başlıyor!

25.2 Ek Argümanları Alma

Tüm bunların çalışması için <stdarg.h> başlık dosyasını dahil etmek isteyeceksiniz.

İlk olarak, bir seferde hangi değişkene eriştiğimizi takip etmek için va_list (değişken argüman listesi) türünde özel bir değişken kullanacağız.

Fikir şudur: önce va_start() çağrısıyla argümanları işlemeye başlarız, sırasıyla her argümanı va_arg() ile işleriz ve ardından bittiğinde va_end() ile işlemi tamamlarız.

va_start() fonksiyonunu çağırdığınızda, ek argümanları nerede aramaya başlayacağını bilmesi için en son isimlendirilmiş parametreyi (tam olarak ... öncesindeki parametreyi) geçirmelisiniz.

Ve bir sonraki argümanı almak için va_arg() fonksiyonunu çağırdığınızda, bir sonraki alınacak argümanın türünü söylemeniz gerekir.

İşte rastgele sayıda tamsayıyı toplayan bir gösterim. İlk argüman toplanacak tamsayıların sayısıdır. va_arg() fonksiyonunu kaç kez çağırmamız gerektiğini anlamak için bundan yararlanacağız.

#include <stdio.h>
#include <stdarg.h>

int add(int count, ...)
{
    int total = 0;
    va_list va;

    va_start(va, count);   // "count" sonrasındaki argümanlarla başla

    for (int i = 0; i < count; i++) {
        int n = va_arg(va, int);   // Bir sonraki int değerini al

        total += n;
    }

    va_end(va);  // Hepsi bitti

    return total;
}

int main(void)
{
    printf("%d\n", add(4, 6, 2, -4, 17));  // 6 + 2 - 4 + 17 = 21
    printf("%d\n", add(2, 22, 44));        // 22 + 44 = 66
}

(printf() çağrıldığında, kaç tane daha argüman olduğunu bilmek için biçim metnindeki %d (veya her neyse) sayısını kullandığına dikkat edin!)

Eğer va_arg() sözdizimi size garip görünüyorsa (içeride dolaşan o bağımsız tür adı yüzünden), yalnız değilsiniz. İçerideki tüm o sihirli işleri yapmak için bunlar ön işlemci makroları (preprocessor macros) ile uygulanmıştır.

25.3 va_list İşlevselliği

Yukarıda kullandığımız o va_list değişkeni nedir? va_arg() ile bir sonraki aşamada hangi argümanı alacağımız bilgisini tutan opak (opaque) bir değişkendir154. Nasıl tekrar tekrar va_arg() çağırdığımızı görüyorsunuz değil mi? va_list değişkeni, şimdiye kadarki ilerlemeyi takip eden bir yer tutucudur (placeholder).

Ancak bu değişkeni mantıklı bir değere ilklendirmemiz gerekiyor. İşte va_start() burada devreye girer.

Yukarıda va_start(va, count) çağırdığımızda, “va değişkenini, count parametresinden hemen sonraki değişken argümanı gösterecek şekilde ilklendir” demiş oluyorduk.

Ve argüman listemizde neden en az bir isimlendirilmiş değişkene sahip olmamız gerektiğinin sebebi de tam olarak budur155.

İlk parametreye olan o göstericiye sahip olduğunuzda, tekrar tekrar va_arg() çağırarak sonraki argüman değerlerini kolayca alabilirsiniz. Bunu yaptığınızda, va_list değişkeninizi (nerede olduğunuzu takip etmeye devam edebilmesi için) ve kopyalamak üzere olduğunuz argümanın türünü geçirmelisiniz.

va_arg() fonksiyonuna hangi türü geçireceğinizi bulmak bir programcı olarak size kalmıştır. Yukarıdaki örnekte sadece int türlerini kullandık. Ancak printf() durumunda, bir sonraki aşamada hangi türün çekileceğini belirlemek için biçim belirteçlerini (format specifiers) kullanır.

Ve bittiğinde, işlemi sonlandırmak için va_end() fonksiyonunu çağırın. O va_list değişkeni üzerinde tekrar va_start() veya va_copy() çağırmaya karar vermeden önce bunu o değişken üzerinde çağırmalısınız (standart spesifikasyonu öyle söylüyor). Henüz va_copy() konusundan bahsetmediğimizi biliyorum.

Yani standart ilerleyiş şöyledir:

  • va_list değişkeninizi ilklendirmek için va_start()
  • Değerleri almak için tekrar tekrar va_arg()
  • va_list değişkeninizi sonlandırmak için va_end()

Yukarıda va_copy() fonksiyonundan da bahsetmiştim; bu, va_list değişkeninizin birebir aynı durumdaki bir kopyasını oluşturur. Yani kaynak değişkenle henüz va_arg() işlemine başlamadıysanız yeni olan da başlamamış olacaktır. Şimdiye kadar va_arg() ile 5 değişken tükettiyseniz kopya da bunu yansıtacaktır.

va_copy(), argümanları önceden taramanız gerektiğinde ancak mevcut yerinizi de hatırlamanız gerekiyorsa yararlı olabilir.

25.4 va_list Kullanan Kütüphane Fonksiyonları

Bunların diğer kullanımlarından biri oldukça havalıdır: kendi özel printf() varyantınızı yazmak. Tüm o biçim belirteçlerini tek tek işlemek zorunda kalmak bir eziyet olurdu değil mi? O milyarlarca belirteci?

Neyse ki, çalışan bir va_list yapısını argüman olarak kabul eden printf() varyantları vardır. Kendi özel printf() fonksiyonlarınızı sarmalamak ve oluşturmak için bunları kullanabilirsiniz!

Bu fonksiyonlar vprintf(), vfprintf(), vsprintf() ve vsnprintf() gibi v harfi ile başlar. Temel olarak önünde bir v olan tüm o bildiğiniz klasikler.

En başta ekstra bir argüman alması dışında tıpkı printf() gibi çalışan bir my_printf() fonksiyonu yapalım.

#include <stdio.h>
#include <stdarg.h>

int my_printf(int serial, const char *format, ...)
{
    va_list va;
    int rv;

    // Kendi özel işimi yapıyorum
    printf("The serial number is: %d\n", serial);

    // Ardından gerisini vprintf() fonksiyonuna devret
    va_start(va, format);
    rv = vprintf(format, va);
    va_end(va);

    return rv;
}

int main(void)
{
    int x = 10;
    float y = 3.2;

    my_printf(3490, "x is %d, y is %f\n", x, y);
}

Orada ne yaptığımızı gördünüz mü? 13-15. satırlarda yeni bir va_list değişkeni başlattık ve sonra onu doğrudan vprintf() fonksiyonuna geçirdik. Ve o bununla ne yapacağını çok iyi biliyor, çünkü tüm o printf() zekası içinde yerleşik olarak geliyor.

Yine de işimiz bittiğinde va_end() çağırmamız gerekiyor, bu yüzden bunu unutmayın!

25.5 Variadic Makro Püf Noktaları ve Tuzakları

Bahsettiğim gibi, va_start() ve va_end() makrolar olabilir. Bunun sonuçlarından biri, potansiyel olarak yeni bir yerel kapsam (local scope) başlatabilecek olmalarıdır. (Yani va_start() açılış parantezi { içeriyorsa ve va_end() kapanış parantezi } içeriyorsa.)

Bu nedenle potansiyel kapsam sorunlarına dikkat etmemiz gerekiyor. Şu örneği ele alalım:

va_start(va, format);          // { içerebilir
int rv = vprintf(format, va);
va_end(va);                    // } içerebilir

return rv;

Eğer va_start() yeni bir kapsam açarsa, rv o kapsama yerel olacak ve ardından return ifadesi başarısız olacaktır. Ancak bu sinsi durum yalnızca va makrolarını o şekilde uygulayan derleyicilerde gerçekleşecektir.
