20 struct II: struct Yapıları ile Daha Fazla Eğlence

Görünen o ki struct yapılarıyla yapabileceğiniz şeylerin sayısı şimdiye kadar bahsettiğimizden çok daha fazla; ancak bunlar çeşitli konuların bir araya geldiği bir yığın. Bu yüzden hepsini bu bölümde toplayacağız.

Eğer struct temellerine hakimseniz, bilginizi burada tamamlayabilirsiniz.

20.1 İç İçe Geçmiş struct Yapılarının ve Dizilerin İlklendiricileri

Yapı üyelerini şu şekilde ilklendirebildiğinizi (initialize) hatırlıyor musunuz?

struct foo x = {.a=12, .b=3.14};

Meğer bu ilklendiricilerde başlangıçta paylaştığımızdan çok daha fazla güce sahipmişiz. Heyecan verici!

Birincisi, aşağıdaki gibi iç içe geçmiş bir alt yapınız (substructure) varsa, değişken adlarını sırayla takip ederek o alt yapının üyelerini ilklendirebilirsiniz:

struct foo x = {.a.b.c=12};

Bir örneğe bakalım:

#include <stdio.h>

struct cabin_information {
    int window_count;
    int o2level;
};

struct spaceship {
    char *manufacturer;
    struct cabin_information ci;
};

int main(void)
{
    struct spaceship s = {
        .manufacturer="General Products",
        .ci.window_count = 8,   // <-- İÇ İÇE GEÇMİŞ İLKLENDİRİCİ!
        .ci.o2level = 21
    };

    printf("%s: %d seats, %d%% oxygen\n",
        s.manufacturer, s.ci.window_count, s.ci.o2level);
}

17-18. satırlara göz atın! struct spaceship türündeki s değişkenimizin tanımı içinde struct cabin_information üyelerini tam orada ilklendiriyoruz.

Ve işte aynı ilklendirici için başka bir seçenek—bu sefer daha standart görünen bir şey yapacağız, ancak her iki yaklaşım da çalışır:

    struct spaceship s = {
        .manufacturer="General Products",
        .ci={
            .window_count = 8,
            .o2level = 21
        }
    };

Şimdi, yukarıdaki bilgiler yeterince muhteşem değilmiş gibi, işin içine dizi ilklendiricilerini de katabiliriz.

Araya bir yolcu bilgisi dizisi eklemek için bunu biraz değiştirelim ve ilklendiricilerin burada da nasıl çalıştığını görelim.

#include <stdio.h>

struct passenger {
    char *name;
    int covid_vaccinated; // Mantıksal (Boolean)
};

#define MAX_PASSENGERS 8

struct spaceship {
    char *manufacturer;
    struct passenger passenger[MAX_PASSENGERS];
};

int main(void)
{
    struct spaceship s = {
        .manufacturer="General Products",
        .passenger = {
            // Her seferinde bir alanı ilklendir
            [0].name = "Gridley, Lewis",
            [0].covid_vaccinated = 0,

            // Veya hepsini tek seferde
            [7] = {.name="Brown, Teela", .covid_vaccinated=1},
        }
    };

    printf("Passengers for %s ship:\n", s.manufacturer);

    for (int i = 0; i < MAX_PASSENGERS; i++)
        if (s.passenger[i].name != NULL)
            printf("    %s (%svaccinated)\n",
                s.passenger[i].name,
                s.passenger[i].covid_vaccinated? "": "not ");
}

20.2 Adsız (Anonim) struct Yapıları

Bunlar “adı olmayan struct” yapılarıdır. Bunlardan typedef bölümünde de bahsetmiştik, ama burada hafızamızı tazeleyeceğiz.

İşte normal bir struct:

struct animal {
    char *name;
    int leg_count, speed;
};

Ve işte anonim karşılığı:

struct {              // <-- Adı yok!
    char *name;
    int leg_count, speed;
};

Tamammm. Yani bir struct yapımız var ama adı yok, bu yüzden daha sonra kullanmamızın bir yolu yok mu? Oldukça anlamsız görünüyor.

Kabul etmek gerekir ki, bu örnekte gerçekten de öyle. Ancak yine de ondan birkaç farklı şekilde yararlanabiliriz.

Biri nadir kullanılır, ancak anonim struct bir türü temsil ettiği için, hemen arkasına bazı değişken adları koyup bunları kullanabiliriz.

struct {                   // <-- Adı yok!
    char *name;
    int leg_count, speed;
} a, b, c;                 // Bu struct türünde 3 değişken

a.name = "antelope";
c.leg_count = 4;           // örneğin

Fakat bu da hâlâ o kadar kullanışlı değil.

Çok daha yaygın olanı, daha sonra kullanabilmemiz için (örneğin değişkenleri fonksiyonlara geçirmek amacıyla) typedef ile birlikte anonim struct yapıları kullanmaktır.

typedef struct {                   // <-- Adı yok!
    char *name;
    int leg_count, speed;
} animal;                          // Yeni tür: animal

animal a, b, c;

a.name = "antelope";
c.leg_count = 4;           // örneğin

Şahsen ben pek fazla anonim struct kullanmam. Bir bildirimde değişken adından önce tüm struct animal ifadesini görmenin daha hoş olduğunu düşünüyorum.

Ama hey, bu sadece benim fikrim dostum.

20.3 Öz-Referanslı (Self-Referential) struct Yapıları

Graf benzeri herhangi bir veri yapısı için, bağlı düğümlere/köşelere (nodes/vertices) göstericilere (pointers) sahip olmak kullanışlıdır. Ancak bu, bir düğümün tanımı içinde yine bir düğüme gösterici bulundurmanız gerektiği anlamına gelir. Tam bir tavuk mu yumurtadan yumurta mı tavuktan durumu!

Fakat görünüşe göre C dilinde bunu hiçbir sorun yaşamadan yapabilirsiniz.

Örneğin, işte bir bağlı liste (linked list) düğümü:

struct node {
    int data;
    struct node *next;
};

next elemanının bir gösterici olduğunu unutmamak önemlidir. Tüm yapının derlenebilmesini sağlayan şey de budur. Derleyici henüz struct node yapısının tamamının neye benzediğini bilmese bile, tüm göstericiler aynı boyuttadır.

Bunu test etmek için basit bir bağlı liste programı:

#include <stdio.h>
#include <stdlib.h>

struct node {
    int data;
    struct node *next;
};

int main(void)
{
    struct node *head;

    // Hızlıca bir bağlı liste oluştur: (11)->(22)->(33)
    head = malloc(sizeof(struct node));
    head->data = 11;
    head->next = malloc(sizeof(struct node));
    head->next->data = 22;
    head->next->next = malloc(sizeof(struct node));
    head->next->next->data = 33;
    head->next->next->next = NULL;

    // Liste üzerinde gezin (traverse)
    for (struct node *cur = head; cur != NULL; cur = cur->next) {
        printf("%d\n", cur->data);
    }
}

Bunu çalıştırmak şunu yazdırır:

11
22
33

20.4 Esnek Dizi Üyeleri (Flexible Array Members)

Eski güzel günlerde, insanlar C kodunu ahşaptan yontarken, bazıları sonlarında değişken uzunluklu diziler (variable length arrays) bulunan struct yapıları tahsis edebilseler harika olacağını düşündü.

Şunu açıkça belirteyim ki, bu bölümün ilk kısmı işlerin eski yapılma şeklidir; bundan sonra işleri yeni yöntemle yapacağız.

Örneğin, metin dizilerini (strings) ve o metnin uzunluğunu tutmak için bir struct tanımlayabilirsiniz. Verileri tutmak için bir uzunluk alanına ve bir diziye sahip olurdu. Belki şöyle bir şey:

struct len_string {
    int length;
    char data[8];
};

Ancak bu yapı bir metin dizisinin maksimum uzunluğu olarak sabit kodlanmış 8 değerine sahiptir ve bu pek fazla değildir. Ya akıllıca bir şey yapıp yapının hemen arkasından malloc() ile biraz ekstra alan tahsis etseydik ve ardından verilerin o alana taşmasına (overflow) izin verseydik?

Gelin bunu yapalım ve üzerine 40 bayt daha tahsis edelim:

struct len_string *s = malloc(sizeof *s + 40);

data yapının son alanı olduğu için, o alanı taşırdığımızda zaten tahsis etmiş olduğumuz alana doğru taşar! Bu nedenle, bu hile yalnızca kısa dizi struct yapısındaki son alan olduğunda çalışır.

// 8 bayttan fazlasını kopyala!

strcpy(s->data, "Hello, world!");  // Çökmez. Muhtemelen.

Hatta bunu yapmak için sonuna sıfır uzunluklu bir dizi tahsis ettiğiniz yaygın bir derleyici geçici çözümü (workaround) vardı:

struct len_string {
    int length;
    char data[0];
};

Ve böylece tahsis ettiğiniz her ekstra bayt o metin dizisinde kullanılmaya hazır hale gelirdi.

data yapının son alanı olduğu için, o alanı taşırdığımızda zaten tahsis etmiş olduğumuz alana doğru taşar!

// 8 bayttan fazlasını kopyala!

strcpy(s->data, "Hello, world!");  // Çökmez. Muhtemelen.

Ancak elbette, o dizinin sonunun ötesindeki veriye erişmek tanımsız davranıştır (undefined behavior)! Bu modern zamanlarda artık böyle barbarca yöntemlere tenezzül etmiyoruz.

Şansımıza, C99 ve sonrasında aynı etkiyi elde edebiliyoruz, üstelik artık tamamen yasal.

Yukarıdaki tanımımızı dizi boyutu olmayacak şekilde değiştirelim135:

struct len_string {
    int length;
    char data[];
};

Yine belirtelim, bu yalnızca esnek dizi üyesi (flexible array member) struct içindeki son alan olduğunda çalışır.

Ve sonra, bir C metin dizisinden (string) yeni bir struct len_string oluşturan bu örnekte yaptığımız gibi, struct len_string yapısından daha büyük bir alanı malloc() ile tahsis ederek bu metin dizileri için istediğimiz tüm alanı ayırabiliriz:

struct len_string *len_string_from_c_string(char *s)
{
    int len = strlen(s);

    // Normalde ihtiyacımız olandan "len" bayt daha fazla tahsis et
    struct len_string *ls = malloc(sizeof *ls + len);

    ls->length = len;

    // Metni bu ekstra baytlara kopyala
    memcpy(ls->data, s, len);

    return ls;
}

20.5 struct Doldurma Baytları (Padding Bytes)

C dilinin uygun gördüğü şekilde bir struct içinde veya sonrasında doldurma baytları (padding bytes) eklesine izin verildiğini unutmayın. Bellekte doğrudan yan yana olacaklarına güvenemezsiniz136.

Bu programa bir göz atalım. İki sayı yazdırıyoruz. Biri ayrı ayrı alan türlerinin sizeof toplamıdır. Diğeri ise tüm struct yapısının sizeof değeridir.

İnsan bunların aynı olmasını bekler. Toplamın boyutu, parçalarının boyutunun toplamıdır, değil mi?

#include <stdio.h>

struct foo {
    int a;
    char b;
    int c;
    char d;
};

int main(void)
{
    printf("%zu\n", sizeof(int) + sizeof(char) + sizeof(int) + sizeof(char));
    printf("%zu\n", sizeof(struct foo));
}

Ancak benim sistemimde bu şunu yazdırır:

10
16

Aynı değiller! Derleyici, daha performanslı olmasına yardımcı olmak için 6 baytlık doldurma (padding) eklemiştir. Belki derleyicinizle farklı bir çıktı aldınız, ancak bunu zorlamadığınız sürece doldurma baytı olmadığından emin olamazsınız.

20.6 offsetof

Önceki bölümde derleyicinin bir yapı içine istediği gibi doldurma baytları enjekte edebildiğini gördük.

Ya bunların nerede olduğunu bilmemiz gerekirse? Bunu <stddef.h> içinde tanımlanan offsetof ile ölçebiliriz.

Yukarıdaki kodu, struct içindeki bireysel alanların ofsetlerini (offsets) yazdıracak şekilde değiştirelim:

#include <stdio.h>
#include <stddef.h>

struct foo {
    int a;
    char b;
    int c;
    char d;
};

int main(void)
{
    printf("%zu\n", offsetof(struct foo, a));
    printf("%zu\n", offsetof(struct foo, b));
    printf("%zu\n", offsetof(struct foo, c));
    printf("%zu\n", offsetof(struct foo, d));
}

Benim için bu şunu yazdırır:

0
4
8
12

bu da alanların her biri için 4 bayt kullandığımızı gösterir. Biraz garip, çünkü char sadece 1 bayttır, değil mi? Derleyici, tüm alanların 4 bayt uzunluğunda olması için her char değerinden sonra 3 doldurma baytı koyuyor. Muhtemelen bu işlemci üzerinde daha hızlı çalışacaktır.

20.7 Sahte OOP (Nesne Yönelimli Programlama)

struct yapılarıyla yapabileceğiniz, bir nevi Nesne Yönelimli Programlama (OOP) benzeri hafif suistimal edici bir şey var.

struct yapısına olan gösterici (pointer), struct yapısının ilk elemanına olan gösterici ile aynı olduğu için, struct göstericisini ilk elemanın göstericisine serbestçe dönüştürebilirsiniz (cast).

Bu, şöyle bir durum kurabileceğimiz anlamına gelir:

struct parent {
    int a, b;
};

struct child {
    struct parent super;  // İLK sırada OLMALIDIR
    int c, d;
};

Böylece struct child göstericisini, ya bunu ya da bir struct parent göstericisini bekleyen bir fonksiyona geçirebiliriz!

Çünkü struct parent super, struct child yapısındaki ilk ögedir; herhangi bir struct child göstericisi o super alanına olan gösterici ile aynıdır137.

Gelin burada bir örnek oluşturalım. Yukarıdaki gibi struct yapıları yapacağız, ancak sonra bir struct parent göstericisine ihtiyaç duyan bir fonksiyona struct child göstericisi geçireceğiz... ve bu yine de çalışacak.

#include <stdio.h>

struct parent {
    int a, b;
};

struct child {
    struct parent super;  // İLK sırada OLMALIDIR
    int c, d;
};

// İçine herhangi bir tür geçirebilmemiz için argümanı void* yapıyoruz
// (yani bir struct parent veya struct child)
void print_parent(void *p)
{
    // Bir struct parent bekler--ancak bir struct child da çalışır
    // çünkü gösterici ilk alandaki struct parent'ı gösterir:
    struct parent *self = p;

    printf("Parent: %d, %d\n", self->a, self->b);
}

void print_child(struct child *self)
{
    printf("Child: %d, %d\n", self->c, self->d);
}

int main(void)
{
    struct child c = {.super.a=1, .super.b=2, .c=3, .d=4};

    print_child(&c);
    print_parent(&c);  // Bir struct child olmasına rağmen bu da çalışır!
}

main() fonksiyonunun son satırında ne yaptığımızı gördünüz mü? print_parent() fonksiyonunu çağırdık ama argüman olarak bir struct child* geçirdik! print_parent() fonksiyonunun bir struct parent'ı gösteren argümana ihtiyacı olmasına rağmen, struct child içindeki ilk alan bir struct parent olduğu için bunu yanımıza kâr kalacak şekilde başardık.

Yineleyelim, bu çalışır çünkü bir struct göstericisi, o struct yapısının ilk alanının göstericisiyle aynı değere sahiptir.

Tüm bunlar standart spesifikasyonunun şu bölümüne dayanır:

§6.7.2.1¶15 […] Uygun şekilde dönüştürülmüş bir yapı nesnesi göstericisi, onun ilk üyesini gösterir […], ve tersi de geçerlidir.

ve

§6.5¶7 Bir nesnenin saklanan değerine yalnızca aşağıdaki türlerden birine sahip bir sol-taraf ifadesi (lvalue expression) ile erişilebilir:

  • nesnenin etkin türü ile uyumlu bir tür
  • […]

ve benim "uygun şekilde dönüştürülmüş" ifadesinin "ilk üyenin etkin türüne dönüştürülmüş (cast)" anlamına geldiği yönündeki varsayımım.

20.8 Bit Alanları (Bit-Fields)

Deneyimlerime göre bunlar nadiren kullanılır, ancak zaman zaman özellikle bitleri daha büyük alanlarda paketleyen alt seviye uygulamalarda görebilirsiniz.

Bir kullanım durumunu göstermek için bazı kodlara göz atalım:

#include <stdio.h>

struct foo {
    unsigned int a;
    unsigned int b;
    unsigned int c;
    unsigned int d;
};

int main(void)
{
    printf("%zu\n", sizeof(struct foo));
}

Benim için bu 16 yazdırır. Bu da mantıklıdır, çünkü benim sistemimde unsigned türleri 4 bayttır.

Peki ya a ve b içinde saklanacak tüm değerlerin 5 bitte, c ve d içindeki değerlerin ise 3 bitte saklanabileceğini bilseydik? Bu toplamda sadece 16 bittir. Sadece 16 bit kullanacaksak neden onlar için 128 bit ayrılsın ki?

C'ye bu değerleri paketlemeye çalışmasını tatlılıkla söyleyebiliriz. Değerlerin alabileceği maksimum bit sayısını belirtebiliriz (1'den kapsayan türün boyutuna kadar).

Bunu alan adından sonra bir iki nokta üst üste ve ardından bit cinsinden alan genişliğini koyarak yaparız.

struct foo {
    unsigned int a:5;
    unsigned int b:5;
    unsigned int c:3;
    unsigned int d:3;
};

Şimdi C'ye struct foo yapımın ne kadar büyük olduğunu sorduğumda bana 4 diyor! 16 bayttı ama şimdi sadece 4. Bu 4 değeri 4 bayta "paketledi", bu da bellek açısından dört kat tasarruf anlamına gelir.

Dezavantajı elbette 5 bitlik alanların yalnızca 0-31 arasındaki değerleri ve 3 bitlik alanların yalnızca 0-7 arasındaki değerleri tutabilmesidir. Ama ne de olsa hayat uzlaşılarla doludur.

20.8.1 Bitişik Olmayan Bit Alanları

Bir püf noktası: C yalnızca bitişik bit alanlarını birleştirecektir. Aralarına bit alanı olmayan ögeler girerse hiçbir tasarruf elde edemezsiniz:

struct foo {            // sizeof(struct foo) == 16 (benim için)
    unsigned int a:1;   // a, c ile bitişik olmadığı için.
    unsigned int b;
    unsigned int c:1;
    unsigned int d;
};

Bu örnekte a, c ile bitişik olmadığı için her ikisi de kendi int türleri içinde "paketlenir".

Yani a, b, c ve d için birer int yapımız var. Benim int türlerim 4 bayt olduğundan, bu toplamda 16 bayt eder.

Hızlı bir yeniden düzenleme 16 bayttan 12 bayta (benim sistemimde) bir alan tasarrufu sağlar:

struct foo {            // sizeof(struct foo) == 12 (benim için)
    unsigned int a:1;
    unsigned int c:1;
    unsigned int b;
    unsigned int d;
};

Ve şimdi a, c'nin yanında olduğu için derleyici bunları tek bir int içinde birleştirir.

Böylece birleştirilmiş a ve c için bir int, b ve d için birer int elde ederiz. Genel toplamda 3 int yani 12 bayt.

Derleyicinin bunları birleştirmesini sağlamak için tüm bit alanlarınızı bir araya toplayın.

20.8.2 İşaretli veya İşaretsiz int Türleri

Bir bit alanını yalnızca int olarak bildirirseniz, farklı derleyiciler bunu signed veya unsigned olarak ele alacaktır. Tıpkı char durumunda olduğu gibi.

Bit alanlarını kullanırken işaretli/işaretsiz (signedness) durumunu açıkça belirtin.

20.8.3 İsimsiz Bit Alanları

Bazı özel durumlarda donanımsal nedenlerle bazı bitleri ayırmanız gerekebilir, ancak bunları kodda kullanmanız gerekmeyebilir.

Örneğin, üst 2 bitin bir anlamı olduğu, en alttaki 1 bitin bir anlamı olduğu, ancak ortadaki 5 bitin sizin tarafınızdan kullanılmadığı bir baytınız olduğunu varsayalım138.

Şöyle bir şey yapabilirdik:

struct foo {
    unsigned char a:2;
    unsigned char dummy:5;
    unsigned char b:1;
};

Ve bu çalışır—kodumuzda a ve b kullanırız ama asla dummy kullanmayız. Sadece a ve b'nin bayt içinde "gerekli" (bu kurgusal örnekte belirtilen) konumlarda olduğundan emin olmak amacıyla 5 bit harcamak için oradadır.

C bize bunu temizlemenin bir yolunu sunar: isimsiz bit alanları (unnamed bit-fields). Bu durumda adı (dummy) tamamen bırakabilirsiniz ve C aynı etki için bunu memnuniyetle karşılar:

struct foo {
    unsigned char a:2;
    unsigned char :5;   // <-- isimsiz bit alanı!
    unsigned char b:1;
};

20.8.4 Sıfır Genişlikli İsimsiz Bit Alanları

Burada biraz daha derin detaylar var... Diyelim ki bitleri bir unsigned int içine paketliyordunuz ve bazı bitişik bit alanlarının bir sonraki unsigned int içine paketlenmesine ihtiyaç duydunuz.

Yani bunu yaparsanız:

struct foo {
    unsigned int a:1;
    unsigned int b:2;
    unsigned int c:3;
    unsigned int d:4;
};

derleyici tüm bunları tek bir unsigned int içinde paketler. Peki ya bir int içinde a ve b'ye, farklı bir int içinde ise c ve d'ye ihtiyacınız varsa?

Bunun bir çözümü var: derleyicinin farklı bir int içinde bitleri paketlemeye yeniden başlamasını istediğiniz yere 0 genişliğinde isimsiz bir bit alanı koyun:

struct foo {
    unsigned int a:1;
    unsigned int b:2;
    unsigned int :0;   // <-- Sıfır genişlikli isimsiz bit alanı
    unsigned int c:3;
    unsigned int d:4;
};

Bu, bir kelime işlemcideki açık sayfa sonuna (page break) benzer. Derleyiciye "Bu unsigned içinde bit paketlemeyi durdur ve bir sonrakinde paketlemeye başla" diyorsunuz.

O noktaya sıfır genişlikli isimsiz bit alanını ekleyerek derleyici a ve b'yi bir unsigned int içine, c ve d'yi ise başka bir unsigned int içine koyar. Benim sistemimde toplam iki tane, yani 8 baytlık bir boyut (unsigned int türlerinin her biri 4 bayttır).

20.9 Birlikler: union

Bunlar temel olarak struct yapılarına benzer, ancak alanlar bellekte üst üste biner. union yalnızca en büyük alan için yeterli boyutta olacaktır ve aynı anda yalnızca bir alan kullanabilirsiniz.

Farklı veri türleri için aynı bellek alanını yeniden kullanmanın bir yoludur.

union olması dışında tıpkı struct yapıları gibi bildirirsiniz. Şuna bir bakın:

union foo {
    int a, b, c, d, e, f;
    float g, h;
    char i, j, k, l;
};

İşte bu çok fazla alan demek. Bu bir struct olsaydı, sistemim hepsini tutmak için 36 bayt gerektiğini söylerdi.

Fakat bu bir union yapısıdır, bu nedenle tüm o alanlar aynı bellek uzamında üst üste biner. En büyüğü benim sistemimde 4 bayt yer kaplayan int (veya float) türüdür. Ve gerçekten de union foo için sizeof sorduğumda bana 4 yanıtını verir!

Dezavantajı, taşınabilir bir şekilde aynı anda yalnızca bu alanlardan birini kullanabilmenizdir. Ancak…

20.9.1 Birlikler ve Tür Kelime Oyunu (Type Punning)

Taşınabilir olmayan bir şekilde bir union alanına yazıp başka bir alandan okuyabilirsiniz!

Bunu yapmaya tür kelime oyunu (type punning)139 denir ve bunu genellikle bir tür alt seviye programlamada, gerçekten ne yaptığınızı biliyorsanız kullanırsınız.

Bir birliğin (union) üyeleri aynı belleği paylaştığından, bir üyeye yazmak zorunlu olarak diğerlerini etkiler. Ve birine yazılanı diğerinden okursanız garip etkiler elde edersiniz.

#include <stdio.h>

union foo {
    float b;
    short a;
};

int main(void)
{
    union foo x;

    x.b = 3.14159;

    printf("%f\n", x.b);  // 3.14159, oldukça makul

    printf("%d\n", x.a);  // Peki ya bu?
}

Benim sistemimde bu şunu yazdırır:

3.141590
4048

çünkü kaputun altında 3.14159 float değerinin nesne gösterimi (object representation), 4048 short değerinin nesne gösterimi ile aynıydı. Benim sistemimde. Sizin sonuçlarınız farklılık gösterebilir.

20.9.2 union Göstericileri (Pointers)

Bir union göstericisine (pointer) sahipseniz, o göstericiyi o union içindeki alanların türlerinden herhangi birine dönüştürebilir (cast) ve değerleri bu şekilde alabilirsiniz.

Bu örnekte union içinde int ve float türlerinin olduğunu görüyoruz. Ve union göstericileri elde ediyoruz ama bunları int* ve float* türlerine dönüştürüyoruz (bu tür dönüşümü derleyici uyarılarını susturur). Ve daha sonra bu göstericileri başvuru dışı bıraktığımızda (dereference), doğrudan union içinde sakladığımız değerlere sahip olduklarını görürüz.

#include <stdio.h>

union foo {
    int a, b, c, d, e, f;
    float g, h;
    char i, j, k, l;
};

int main(void)
{
    union foo x;

    int *foo_int_p = (int *)&x;
    float *foo_float_p = (float *)&x;

    x.a = 12;
    printf("%d\n", x.a);           // 12
    printf("%d\n", *foo_int_p);    // 12, yine

    x.g = 3.141592;
    printf("%f\n", x.g);           // 3.141592
    printf("%f\n", *foo_float_p);  // 3.141592, yine
}

Tersi de geçerlidir. union içindeki bir türün göstericisine sahipsek, bunu union göstericisine dönüştürebilir ve üyelerine erişebiliriz.

union foo x;
int *foo_int_p = (int *)&x;             // int alanına gösterici
union foo *p = (union foo *)foo_int_p;  // Tekrar union göstericisine

p->a = 12;  // Bu satır şununla aynıdır...
x.a = 12;   // bu satır.

Tüm bunlar size kaputun altında union içindeki tüm bu değerlerin bellekte aynı yerden başladığını ve bunun tüm union yapısının bulunduğu yerle aynı olduğunu bildirir.

20.9.3 Birliklerde Ortak Başlangıç Dizilimleri (Common Initial Sequences)

struct yapılarından oluşan bir union yapınız varsa ve tüm o struct yapıları bir ortak başlangıç dizilimi (common initial sequence) ile başlıyorsa, union üyelerinin herhangi birinden o dizilimin üyelerine erişmek geçerlidir.

Ne?

İşte ortak başlangıç dizilimine sahip iki struct:

struct a {
    int x;     //
    float y;   // Ortak başlangıç dizilimi

    char *p;
};

struct b {
    int x;     //
    float y;   // Ortak başlangıç dizilimi

    double *p;
    short z;
};

Görüyor musunuz? int ile başlayıp ardından float ile devam ediyorlar—ortak başlangıç dizilimi işte budur. struct dizilimindeki üyelerin uyumlu türlerde olması gerekir. Bunu sırasıyla int ve float olan x ve y ile görüyoruz.

Şimdi bunlardan bir birlik (union) oluşturalım:

union foo {
    struct a sa;
    struct b sb;
};

Bu kuralın bize söylediği şey, ortak başlangıç dizilimlerinin üyelerinin kod içinde birbirinin yerine geçebilir olduğunun garanti edilmesidir. Yani:

  • f.sa.x ifadesi f.sb.x ile aynıdır.

ve

  • f.sa.y ifadesi f.sb.y ile aynıdır.

Çünkü hem x hem de y alanları ortak başlangıç dizilimindedir.

Ayrıca, ortak başlangıç dizilimindeki üyelerin isimleri önemli değildir—önemli olan tek şey türlerin aynı olmasıdır.

Hepsi bir arada değerlendirildiğinde bu, union içindeki struct yapıları arasında güvenli bir şekilde ortak bilgiler eklememize olanak tanır. Bunun en iyi örneği, muhtemelen union içindeki tüm struct yapılarından hangisinin o anda "kullanımda" olduğunu belirlemek için bir alan kullanmaktır.

Yani buna izin verilmeseydi ve union yapısını bir fonksiyona geçirseydik, o fonksiyon union yapısının bakması gereken üyesinin hangisi olduğunu nasıl bilebilirdi?

Bu struct yapılarına bir göz atın. Ortak başlangıç dizilimine dikkat edin:

#include <stdio.h>

struct common {
    int type;   // ortak başlangıç dizilimi
};

struct antelope {
    int type;   // ortak başlangıç dizilimi

    int loudness;
};

struct octopus {
    int type;   // ortak başlangıç dizilimi

    int sea_creature;
    float intelligence;
};

Şimdi bunları bir union içine koyalım:

union animal {
    struct common common;
    struct antelope antelope;
    struct octopus octopus;
};

Ayrıca gösterim için bu iki #define tanımını hoş görün:

#define ANTELOPE 1
#define OCTOPUS  2

Şu ana kadar özel bir şey olmadı. type alanı tamamen yararsız görünüyor.

Ancak şimdi bir union animal yazdıran genel (generic) bir fonksiyon yapalım. Bir struct antelope yapısına mı yoksa bir struct octopus yapısına mı baktığını bir şekilde anlayabilmesi gerekir.

Ortak başlangıç dizilimlerinin sihri sayesinde, belirli bir union animal x için hayvan türüne bu yerlerin herhangi birinden bakabilir:

int type = x.common.type;    // veya...
int type = x.antelope.type;  // veya...
int type = x.octopus.type;

Tüm bunlar bellekteki aynı değere işaret eder.

Ve tahmin edebileceğiniz gibi, struct common yapısı, kodun belirli bir hayvandan bahsetmeden türü bağımsız olarak inceleyebilmesi için oradadır.

Bir union animal yapısını yazdıran koda bakalım:

void print_animal(union animal *x)
{
    switch (x->common.type) {
        case ANTELOPE:
            printf("Antelope: loudness=%d\n", x->antelope.loudness);
            break;

        case OCTOPUS:
            printf("Octopus : sea_creature=%d\n", x->octopus.sea_creature);
            printf("          intelligence=%f\n", x->octopus.intelligence);
            break;
        
        default:
            printf("Unknown animal type\n");
    }

}

int main(void)
{
    union animal a = {.antelope.type=ANTELOPE, .antelope.loudness=12};
    union animal b = {.octopus.type=OCTOPUS, .octopus.sea_creature=1,
                                       .octopus.intelligence=12.8};

    print_animal(&a);
    print_animal(&b);
}

29. satırda doğrudan union yapısını nasıl geçirdiğimizi gördünüz mü—içinde ne tür bir hayvan struct yapısının kullanımda olduğu hakkında hiçbir fikrimiz yok.

Ama sorun değil! Çünkü 31. satırda bunun bir antilop mu yoksa bir ahtapot mu olduğunu görmek için türe bakıyoruz. Ve ardından üyeleri almak için uygun struct yapısına bakabiliyoruz.

Yalnızca struct yapılarını kullanarak aynı etkiyi elde etmek kesinlikle mümkündür, ancak bir union yapısının bellek tasarrufu sağlayan etkilerini istiyorsanız bu şekilde yapabilirsiniz.

20.10 Birlikler ve İsimsiz Struct Yapıları

Şu şekilde isimsiz bir struct yapısına sahip olabileceğinizi biliyorsunuz:

struct {
    int x, y;
} s;

Bu, x ve y üyelerine sahip anonim bir struct türünde (çünkü struct'ın isim etiketi yok) s değişkenini tanımlar.

Böylece bunun gibi şeyler geçerlidir:

s.x = 34;
s.y = 90;

printf("%d %d\n", s.x, s.y);

Görünüşe göre bu isimsiz struct yapılarını tıpkı bekleyeceğiniz gibi union yapıları içine de koyabilirsiniz:

union foo {
    struct {       // isimsiz!
        int x, y;
    } a;

    struct {       // isimsiz!
        int z, w;
    } b;
};

Ve sonra bunlara normal şekilde erişebilirsiniz:

union foo f;

f.a.x = 1;
f.a.y = 2;
f.b.z = 3;
f.b.w = 4;

Hiç sorun yok!

20.11 struct ve union Yapılarını Fonksiyonlara Geçirme ve Döndürme

Bir struct veya union yapısını fonksiyona değer ile geçebilirsiniz (pass by value) (ona bir gösterici geçmenin aksine)—her zamanki gibi atama yoluyla o nesnenin bir kopyası parametreye aktarılacaktır.

Bir fonksiyondan bir struct veya union da döndürebilirsiniz ve bu da geriye değer ile geçirilir (pass by value).

#include <stdio.h>

struct foo {
    int x, y;
};

struct foo f(void)
{
    return (struct foo){.x=34, .y=90};
}

int main(void)
{
    struct foo a = f();  // Kopya oluşturulur

    printf("%d %d\n", a.x, a.y);
}

Eğlenceli bir bilgi: Eğer bunu yaparsanız, nokta . işlecini doğrudan fonksiyon çağrısı üzerinden kullanabilirsiniz:

    printf("%d %d\n", f().x, f().y);

(Elbette bu örnek fonksiyonu iki kez çağırır, verimsiz bir şekilde.)

Aynı şey struct ve union göstericileri döndürmek için de geçerlidir—sadece bu durumda -> ok işlecini kullandığınızdan emin olun.
